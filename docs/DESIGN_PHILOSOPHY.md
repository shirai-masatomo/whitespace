# WhiteSpace 設計思想

原文：版0.2（2026-09-09）。2026-09-10に重複を整理。主眼・経緯・仮説・未決事項は変更しない。本書は現行仕様でも、将来構想をすべて実装する指示でもない。現在地は [STATUS](STATUS.md)。

## 主眼

**人物・環境・主人公・相互関係を構成し、その組合せから発言や行動の意味が生まれ、やり取りによって状況と関係が変わる仕組みを作る。**

これを「コンテキストの生成・維持・変化」と呼ぶ。コンテキストは人物紹介に限らず、出来事、困り事、望み、知識、責任、過去のやり取りを含む。同じ「ごめん」でも、事故に責任がある人と後から来た人では意味が変わる。その違いをすべて個別に書き切らず、少数の構造の組合せから生み出したい。

省資源化や小型LLMは関心のある手段であって、主眼そのものではない。現在の「宥めよ」、コーヒー場面、3D胸像、モデル、勝敗条件にも固定しない。

## ここに至った経緯

| 試してきたこと | 生まれた問い |
| --- | --- |
| 語彙・辞書候補を増やす | 認識語が増えれば会話は豊かになるか |
| 否定・混在・小型LLMを検討する | 分類できても効果が固定なら同じ遊びではないか |
| 相手を姿勢・光・動きで見せる | 見た目の背後にどんな状態を持つべきか |
| 「再現性しかない」という問題意識 | 相手や事情が違えば、同じ言葉の効果も変わらないか |
| コーヒー場面と関係へ広げる | 感情だけでなく困り事・知識・責任・関係が必要ではないか |
| 四つの核へ整理する | 少ない資源で、一貫した反応と未記述の展開を生めるか |

「再現性しかない」は、事情が違っても効果が固定される問題を指す。同じ条件を再現して検証できることは維持し、理由のない反応の抽選で解決したことにしない。

四つを別々の大きな生成システムとして先行開発せず、一つの場面で育てる。これは構造が反応に寄与するかを確かめる方法であり、プロジェクトを一つの会話ゲームに限定するものではない。

## 四つの外殻と内殻

「外殻」は四つの基本領域、「内殻」はその内側で区別する条件。以下は設計仮説であり、すべてを初期実装する義務はない。

### 対話相手

| 内殻 | 内容の例 |
| --- | --- |
| 安定した傾向 | 接し方、価値観、自分で対処したい等 |
| 現在の感情 | 種類・強さ・混在。苛立ちと悲しみなど |
| 身体・行動 | 泣いている、座っている、手がふさがる |
| 目的・望み | 机を拭きたい、目立ちたくない |
| 困り事 | 拭く物がない等、目的を妨げるもの |
| 知識・認識 | 知ること、信じること、原因の理解 |
| 開示の姿勢 | 誰に何を話すか、詳細を隠すか |

感情・外見・希望を同一視しない。「泣いている＝悲しい」「そっとしてほしい＝援助も不要」と固定しない。

### 環境

| 内殻 | 内容の例 |
| --- | --- |
| 場所・周囲 | カフェ、人目、近くの他者 |
| 物と状態 | カップ、濡れた机、紙の所在・利用可能性 |
| 出来事と原因 | こぼした結果、借りたノートまで濡れた等 |
| 制約 | 時間・資源・できないこと |
| 行動の可能性 | 拭く、店員を呼ぶ、追加注文する |
| 観察できる手がかり | 染み、伏せたノート、視線 |

環境の生成は3D空間全体の自動制作を直ちに意味しない。まず事実と可能な行動として表してよい。

### 主人公

| 内殻 | 内容の例 |
| --- | --- |
| 立場・役割 | 後から来た友人、近くの客 |
| 知識・観察履歴 | こぼした瞬間を見ていない等 |
| 持ち物・能力 | ティッシュ、提供できる援助 |
| 関与の履歴 | カップにぶつかった、声をかけた |
| 目的・選択の範囲 | 助ける、尋ねる、距離を取る |

ゲームが与える立場・既知情報と、ユーザーの意図・判断を区別する。主人公の生成を口実に性格や意図を勝手に決めない。性格値をどこまで設けるかは未決。

### 相互関係

| 内殻 | 内容の例 |
| --- | --- |
| 社会的関係 | 友人、他人、店員と客 |
| 感情的関係 | 信頼、警戒、理解されている感覚 |
| 因果・責任 | 主人公がぶつかった／無関係だった |
| 情報の関係 | 共有済み、本人だけが知る事情 |
| 期待・許容 | 誰にどこまで手伝ってほしいか |
| 物との関係 | 所有・借用・利用可能性 |
| 対話の履歴 | 質問、拒否、約束、開示、援助 |

知識は各人物に、共有・非共有は関係に整理する。ただし、思想上の区分を同じ事実の重複保存の要求としない。

## どう動かすか

発言・行為・出来事について、**解釈 → 条件との照合 → 反応の選択 → 事実の更新 → 表現**を考える。入力には行為・対象・内容・暗黙の前提・断定の強さ・直前とのつながりがある。これは第五の生成対象ではなく、四つの外殻への入力を読む層。

「ティッシュいる？」は提案、「お願い」は受諾、渡すのは実行、拭くのは対処。発言だけで物理結果へ飛ばさない。一方、どこまで行動を省略して表現するか、毎段階を操作させるかは個別のゲーム設計で決められる。

### 設計原則

- **一貫性**：ランダム性は条件の違いを作るために使う。成立しない条件を組み合わせず、出来事なしに事実を変えない。
- **事実・認識・開示の分離**：隠れた事情には手がかりや確認の機会を設け、見えない正解の総当たりにしない。
- **感情と問題解決の分離**：落ち着いても机は濡れたままかもしれず、片付いても借り物への不安は残り得る。
- **不一致も対話を進める**：見当違いには訂正・確認・希望の説明を返せる。未知を即悪意にせず、核心を当てても必ず喜ぶとは限らない。
- **状態と表現の接続**：姿勢・視線・光・物の変化を内部の出来事につなげる。見た目だけに別の事情を持たせない。
- **必要な要素だけ増やす**：「どの反応がなぜ変わるか」を示せないパラメータを先行して増やさない。

## AI・類型・進め方

「大量の例で能力を得るAIに対し、四つの構造から攻める逆のアプローチ」という発想は、省資源で文脈を作る設計動機として保持する。ただし、AI一般を「数を打つだけ」と断定せず、構造の明示と学習済みモデルは併用できる。

必要な構造を明示する方法には、モデルの仕事を狭める利点と、人が構造を設計する手間の両方がある。暫定案は、アプリが事実・状態・更新の許可を保持し、LLMが発言解釈や台詞を助ける分担。性能保証ではなく、対象・省略・前提の扱いを具体例で検証する。MBTI等の人物類型も補助的な候補であり、望み・事情・関係の代わりにせず、型から反応を固定しない。人間心理の正しさを保証する分類とも扱わない。

進め方は、思想の記録 → 一場面 → 条件を一つずつ比較 → 解釈を接続 → 制約付き生成 → 観察・推理 → 他場面。順序は暫定で、全要素を作り込んでから遊べる版にしない。各変更で、主眼との関係、効く外殻、変わる反応、観察方法、再利用できる構造、未確認事項を短く問う。

評価対象は語彙数や設定数だけでなく、文脈に合う反応、一貫性、状態の進展、観察できる手がかり、再利用性、時間・容量・メモリ。MBTI、感情尺度、LLMの担当範囲、勝敗は未決。プレイヤーが観察と対話から理解を更新し、次の関わり方を選べることを目指す。これは現時点の解釈で、完成形を固定しない。
