# WhiteSpace 設計思想書
## コンテキストの生成・維持・変化を核とする試作

版：0.2 ／ 作成日：2026年9月9日

本書は、これまでの対話からプロジェクトの主眼と検討の経緯を整理したものである。実装済み機能の報告書でも、特定のゲームの完成仕様書でもない。後続の場面設計・実装・評価が、何を実現するためのものかを見失わないための基準とする。

## 1. 主眼

**人物・環境・主人公・それらの相互関係を構成し、その組合せから発言や行動の意味が生まれ、やり取りによって状況と関係が変化していく仕組みを作る。**

ここで目指すものを「コンテキストの生成・維持・変化」と呼ぶ。

コンテキストとは、ある発言や行動が、その場でどのような意味を持つかを左右する条件のまとまりである。場所や人物紹介に加え、起きた出来事、困り事、望み、知識、関係、過去のやり取りを含む。

同じ「ごめん」でも、主人公に責任がある場合と、事情を知らずに訪れた場合では意味が異なる。同じ「泣いているの？」でも、気づいてほしい人物と隠したい人物では受け取り方が異なる。この違いを、場面ごとにすべて書き切らず、定義した構造とその組合せから生み出せるようにしたい。

少ない計算機資源で実現することは重要な設計上の関心である。ただし、省資源化や小型LLMの導入そのものを、コンテキストを生むという主眼に置き換えない。

## 2. この思想に至った経緯

| 段階 | 着目したこと | 次に生まれた問い |
| --- | --- | --- |
| 語彙の拡張 | 単語・表現を収集して分類し、入力を認識する | 知っている語を増やせば、会話は豊かになるか |
| 言語解釈の拡張 | 否定、言い換え、混在した意図、小型LLMを検討した | 意味を分類できても、効果が固定なら同じ遊びではないか |
| 相手の可視化 | 無機質な人物を中央に置き、状態を姿勢・光・動きで示す案を採用した | 表示の背後に、どのような内部状態を持たせるか |
| 固定効果への問題意識 | ユーザーは現状を「再現性しかない」と表現した | 相手の個性や状態によって、同じ言葉の効果を変えられないか |
| 場面と関係への拡張 | コーヒーをこぼした相手には「味方だ」より事情の確認や援助が合う場合がある | 感情だけでなく、困り事・知識・責任・関係も必要ではないか |
| コンテキスト生成への整理 | 対話相手、環境、主人公、相互関係という四つの核を提示した | 四つを細分化し、限られた資源で一貫した反応を生めるか |

「再現性しかない」という問題意識は、本書では、相手や事情が異なっても言葉の効果が固定されている問題として扱う。同じ条件を再現して検証できることは維持する。理由のない反応の抽選だけで、この課題を解決したことにはしない。

## 3. 主眼と実現方法を区別する

### 主眼として保持すること

- 同じ言葉・行動の意味が、人物・環境・関係・履歴によって変わる。
- 相手や世界は、やり取りを通じて変化する。
- 変化には、その世界の中で理解できる理由がある。
- プレイヤーは、観察と対話から理解を更新し、次の関わり方を選べる。
- 少数の構成要素から、個別に書き切っていない展開が生まれることを目指す。

### 主眼を検証するために採用した進め方

**①〜④を別々の大きな生成システムとして先行開発せず、一つの場面の中で四つを育てる。**

これは開発を分散させず、構造が実際の反応に寄与するかを確かめるための方法である。プロジェクトの目的をコーヒーの会話ゲームに限定するものではない。現行の「宥めよ」、特定の勝敗条件、3D胸像、使用モデルも変更可能である。

## 4. コンテキストの階層：主眼・外殻・内殻・具体例

「外殻」「内殻」は本書で構造を整理するための呼称とする。外殻を四つの基本領域、内殻を各領域に含まれる具体的な要素として扱う。内殻の一覧は設計仮説であり、すべてを初期実装する義務はない。

| 階層 | 役割 | 例 |
| --- | --- | --- |
| 主眼 | 何を実現するか | 状況に応じて言葉の意味と反応が生まれる |
| 外殻 | 何を構成するか | 対話相手・環境・主人公・相互関係 |
| 内殻 | どの条件を保持するか | 望み、困り事、知識、物、責任、関係の履歴 |
| 具体例 | その場面でどの値や事実を持つか | 友人がコーヒーをこぼし、机を拭きたがっている |

### 外殻① 対話相手の生成

相手が何者であり、何を感じ、何を求め、何を知っているかを構成する。

| 内殻 | 定義する内容 | 具体例 |
| --- | --- | --- |
| 比較的安定した傾向 | 接し方の好み、価値観、表現の仕方 | 自分で対処したい、感情を隠したい |
| 現在の感情 | 種類、強さ、混在 | 苛立ち7、悲しみ3 |
| 身体・行動の状態 | 観察できる姿、可能な動作 | 泣いている、座っている、手がふさがっている |
| 目的・望み | 今どうなってほしいか | 机を拭きたい、目立ちたくない |
| 困り事 | 目的を妨げるもの | 拭く物がない |
| 知識・認識 | 本人が知ること、信じていること | 自分の不注意でこぼしたと認識している |
| 開示の姿勢 | 何を誰に話せるか | 友人には説明するが、失敗の詳細は隠したい |

感情、外見、好みは同一ではない。「泣いている＝悲しい」「そっとしてほしい＝援助も不要」と固定しない。必要な場面では区別できる構造にする。

### 外殻② 環境の生成

場所の見た目に加え、出来事、物、制約、行動の可能性を構成する。

| 内殻 | 定義する内容 | 具体例 |
| --- | --- | --- |
| 場所・周囲 | 場所、他者の存在、周囲の条件 | 人のいるカフェ |
| 物と状態 | 所有者、位置、利用可能性、変化 | 倒れたカップ、濡れた机、紙ナプキン |
| 出来事と原因 | 何が起き、何につながったか | コーヒーをこぼし、借りたノートが濡れた |
| 制約 | 時間、資源、できないこと | 退店まで時間がない、替えの飲み物がない |
| 行動の可能性 | その場で実行できること | 拭く、店員を呼ぶ、追加注文する |
| 観察可能な手がかり | 誰が何を見聞きできるか | 足元の染み、伏せたノート、視線 |

「環境の生成」は、直ちに3D空間全体を自動制作することを意味しない。まず事実と可能な行動として表現してよい。

### 外殻③ 主人公の生成

ユーザーが操作する人物の立場と、知っていること・できることを構成する。

| 内殻 | 定義する内容 | 具体例 |
| --- | --- | --- |
| 立場・役割 | この場にどう関わる人物か | 後から来た友人、近くの席の客 |
| 知識・観察履歴 | 何を見て、何を聞いたか | こぼした瞬間は見ていない |
| 持ち物・能力 | 提供できる援助と実行可能な行動 | ティッシュを持っている |
| 関与の履歴 | これまで何をしたか | カップにぶつかった、先ほど声をかけた |
| 目的・選択の範囲 | ユーザーが何を目指し、選べるか | 助ける、事情を聞く、距離を取る |

主人公の生成は、ユーザーの性格や意図を勝手に決めることではない。ゲームが与える役割・既知情報と、ユーザーが選ぶ発言・判断を区別する。主人公の性格値をどこまで設けるかは未決とする。

### 外殻④ 相互関係の定義

①〜③を結び、単独の設定では表せない文脈を保持する。

| 内殻 | 定義する内容 | 具体例 |
| --- | --- | --- |
| 社会的関係 | 親しさ、役割、距離 | 友人、他人、店員と客 |
| 感情的関係 | 信頼、警戒、理解されている感覚 | 心配はうれしいが、詮索はされたくない |
| 因果・責任 | 誰の行動が何を起こしたか | 主人公がぶつかった／無関係だった |
| 情報の関係 | 何を共有し、何を知らないか | 相手だけがノートの所有者を知っている |
| 期待・許容 | 誰に何を望み、どこまで許すか | 友人には手伝ってほしい |
| 物との関係 | 所有、借用、利用可能性 | ノートは借り物である |
| 対話の履歴 | 質問、拒否、約束、開示、援助 | 「触らないで」と伝えた、援助に同意した |

知識の内容は各人物に、共有・非共有の関係は④に整理する。ただし、これは思想上の区分であり、同じ事実を複数箇所へ重複保存する実装を要求しない。

## 5. 四つの外殻を動かす仕組み

生成後のコンテキストに、発言・行動・出来事が加わる。以下の順序を設計上の基本とする。

1. **解釈する**：何を尋ね、提案し、主張しているか。対象と前提は何か。曖昧さは残るか。
2. **照合する**：人物の望み、事実、知識、関係、履歴にどう合うか。
3. **反応を決める**：説明する、確認する、受け入れる、断る、保留するなど。
4. **更新する**：知識、関係、感情、物や行動の状態を、起きたことに応じて変える。
5. **表現する**：台詞・姿勢・視線・光・物の変化として、観察できる形にする。

発言側で扱う要素は、行為、対象、内容、暗黙の前提、断定の強さ、直前の会話とのつながりなどである。これは第五の生成対象ではなく、四つの外殻への入力を解釈する層とする。

「ティッシュいる？」は提案、「お願い」は受諾、渡す操作は実行、机を拭くことは対処である。発言だけで物理的な結果まで飛ばさない。一方、どこまで行動を省略して表現するかは、個別のゲーム設計で決められる。

## 6. 設計原則

### 6.1 ランダム性と一貫性を両立する

ランダム性は、相手や場面の違いを作るために使う。成立しない条件を無差別に組み合わせない。生成した事実は、出来事がない限り都合よく変えない。検証時には同じ設定を再現できるようにする。

### 6.2 事実・認識・開示を分ける

世界で起きたこと、本人が信じていること、相手に伝えたことは区別する。隠れた事情を持たせる場合も、手がかりや確認の機会を用意し、見えない正解の総当たりにしない。

### 6.3 感情と問題解決を分ける

落ち着いても机は濡れたままかもしれない。片付いても借り物を傷めた不安は残るかもしれない。すべての進行を信頼・緊張だけに集約しない。

### 6.4 不一致も対話を進める

見当違いの質問には、訂正や聞き返し、必要な援助の説明が返り得る。未知の表現を即座に悪意や失敗と扱わない。核心を当てた場合も、必ず喜ぶとは限らず、図星によって緊張が高まることを許す。

### 6.5 内部設定と表現を接続する

人物の視線や動作は、内部状態や出来事とつながるものにする。3D胸像は、相手の状態と手がかりを伝える表現手段として位置づける。見た目だけに別の性格や事情を持たせない。

### 6.6 反応を変えないパラメータを先行して増やさない

新しい内殻を追加するときは、「どの発言・行動への反応が、なぜ変わるか」を具体例で示す。内殻を増やすこと自体を進捗としない。

## 7. AI・小型LLM・人物類型の位置づけ

### AIとの関係

ユーザーは、大量の例から能力を獲得するAIに対し、①〜④の核を明示して攻める方法を「逆のアプローチではないか」と捉えた。この発想を、必要な構造を先に定義して計算負担を狭める設計上の動機として残す。

ただし「AIは数を打って当てるだけ」「本プロジェクトはAIと正反対」といった技術的断定は採用しない。構造の明示と学習済みモデルの利用は併用できる。本書はAI一般の理論を確立するものではない。

### LLMの役割についての暫定案

アプリが事実・状態・許可された更新を保持し、LLMは文脈を含む発言解釈や台詞表現を助ける。モデルに世界設定と結果を毎回一から作らせることを前提にしない。

この分担は設計仮説であり、性能の保証ではない。既存の小型モデルが、対象・省略・前提まで十分に解釈できるかは、具体例で検証する必要がある。必要な構造を明示する方法には、モデルの仕事を狭める利点と、人が構造を設計する手間の両方がある。

### MBTIなどの類型

MBTIを人物生成のステレオタイプ的な入口として用いる案は候補として残す。採用は未決である。タイプ名だけで全反応を決めず、接し方の好みなど、実際の反応に関わる傾向へ落とし込む。人物類型はゲーム用の生成補助であり、人間心理の正しさを保証する分類として扱わない。

## 8. コーヒーの場面は何を検証するか

暫定例：友人が自分でコーヒーをこぼした。苛立ち7、悲しみ3。机を拭きたい。主人公は後から来て事情を知らず、事故には無関係である。

| 入力 | コンテキストとの関係 | 反応・変化の例 |
| --- | --- | --- |
| どうしたの？ | 主人公の情報不足に合う | 「コーヒーこぼしちゃって」と事情が共有される |
| 大丈夫？ | 状態の確認になる | 「けがはないけど、机が……」と困り事が分かる |
| ごめん | 主人公の責任という前提が合わない | 「君のせいじゃないけど」と確認する |
| あなたの味方だ | 現在の具体的な困り事との関連が薄い | 「ありがとう。先にこれ拭きたい」と希望を示す |
| ティッシュいる？ | 困り事に合う提案 | 援助の受諾へ進む。机が乾いたことにはしない |

上記は唯一の正しい反応ではなく、検証用の設定例である。主人公が原因を作った、相手が人目を気にしている、借り物が濡れたなど、一条件を変えて反応がどう変わるかを比べる。

この場面にしか通用しない正解文の一覧を完成させることを目的にしない。差が生じる理由から、ほかの場面にも使える内殻と更新規則を抽出する。

## 9. 主眼を保つロードマップ

| 段階 | 作業 | その段階で確かめること |
| --- | --- | --- |
| 0. 思想の記録 | 本書で主眼・階層・暫定案を整理する | 個別機能の目的を主眼に結びつけられる |
| 1. 一場面の具体化 | 四つの外殻、事実、反応例を手作業で作る | 発言と場面の関係を説明できる |
| 2. 条件比較 | 人物の望み・責任・関係などを一つずつ変える | 同じ発言が理由を持って違う反応を生む |
| 3. 解釈の接続 | 自由入力から行為・対象・前提を読み取る | 言い換えと曖昧さに対応できる |
| 4. 制約付き生成 | 検証した条件から整合する組合せを作る | 未作成の組合せでも事実と反応が破綻しにくい |
| 5. 観察と推理 | 隠れた事情・手がかり・開示・転換を加える | 観察によってプレイヤーの選択が変わる |
| 6. 他場面への移行 | 待ち合わせや紛失などを追加する | 既存の内殻と更新規則を再利用できる |

この順序は暫定であり、成果に応じて変更できる。四つの外殻をすべて同じ深さまで作り込んでから遊べる版を作る進め方は採らない。

## 10. 後続タスクを判断する問い

各場面・機能の設計には、次の事項を短く記録する。

1. 主眼のどの部分を検証するか。
2. どの外殻と内殻を使うか。
3. 何を変えると、同じ発言への反応がどう変わるか。
4. その違いをプレイヤーがどう観察できるか。
5. ほかの場面へ持ち出せる構造は何か。
6. 何が未確認で、どの結果なら設計を見直すか。

評価では、語彙数や設定数だけでなく、文脈に応じる反応、一貫した事実、状態の進展、観察できる手がかり、別場面への再利用、実行時の時間・容量・メモリを確認する。数値目標は実測と遊びの検証から定める。

## 12. この設計が目指す体験

ユーザーが述べた主眼を体験へ翻訳すると、相手・場面・関係を観察し、仮説を持って言葉をかけ、その反応から理解と関わり方を更新する遊びになる。これは現時点の解釈であり、完成形を固定するものではない。

制作上は、少ない構造から書き切っていないやり取りが生まれることを目指す。遊びとしては、その相手のその状況を理解したことで、新しい関わり方や展開が開くことを目指す。

**個々の場面はこの主眼の実験場所であり、場面を増やすことより、そこで何の構造が確かめられたかを蓄積する。**

## 13. 簡素化した別方向：言語ジェンガ

### 13.1 発想と主眼との関係

言語ジェンガは、特定のシチュエーションを複数の言葉群で定義し、そこから任意の単語を差し引くことで、状況が維持されるか、変容するか、崩壊するか、歪な形に変わるかを見届ける構想である。

これはコンテキストを過剰なまでに抽象化・簡素化し、その成立条件を直接操作する試みである。人物の内面や会話を細かく再現する代わりに、状況を支える言葉と関係へ実験対象を絞る。対話型の実装で行き詰まった際の方向性の一つとして保持する。主眼の放棄ではなく、同じ主眼を別の解像度で検証する選択肢と位置づける。

### 13.2 最小の構成

1. 対象とするシチュエーションを一つ定める。
2. その状況を成立させている人物・物・行為・関係・概念を言葉群として表す。
3. プレイヤーが言葉を一つ選び、取り除く。
4. 残った言葉と関係から、状況の変化を表現する。
5. 変化を観察し、さらに何を取り除くかを選ぶ。

主操作は単語の除去とする。単語の追加・置換まで扱うか、自由に入力した語も操作対象にするかは未決である。

### 13.3 仮の例：カフェで友人とコーヒーを飲む

言葉群の例は「二人／友人／カフェ／コーヒー／カップ／会話／待ち合わせ」。以下は仕組みを考えるための解釈例であり、確定した判定規則ではない。

| 取り除く語 | 起こり得る変化 | 検討したいこと |
| --- | --- | --- |
| 会話 | 二人は黙ってコーヒーを飲み続ける | 会話がなくても同じ場面と呼べるか |
| 友人 | 二人はいるが、親しい関係という根拠が失われる | 人物の存在と人物間の関係を分けられるか |
| コーヒー | 二人と場所は残り、飲むという行為の対象がなくなる | 別の場面への変容と崩壊をどう区別するか |
| カップ | 飲み物はあるのに、保持する器がない | 不整合を修復するか、歪さとして残すか |

「カップ」がなくなったからといって、自動で別の器を補えば、除去の効果が消える場合がある。また「友人」の除去が、他人への変化なのか、関係が未定義になることなのかは同じではない。除去が世界からの消失・性質の喪失・説明情報の欠落のどれを意味するか、試作ごとに明示する。

### 13.4 結果の扱いと未決課題

- **維持**：主要な関係や行為が成立し、同じ状況とみなせる。
- **変容**：別の状況として、整合した意味が成立する。
- **崩壊**：その状況を成立させる重要な関係や行為を維持できない。
- **歪な変化**：一部は成立しながら、矛盾や欠落、不自然な関係が残る。

これらは暫定的な観察区分であり、排他的な分類や勝敗条件として固定しない。「崩壊を避ける」だけでなく「どんな歪な状況を作れるか」を楽しむ可能性も残す。

判定を手作業の関係規則で行うか、LLMの解釈を用いるか、組み合わせるかは未決である。LLMを使う場合も、削除した概念を勝手に復元していないか、変化の理由を残った要素から説明できるかを確認する。面白い歪みを作品として扱う実験と、意図せず事実が変わる実装上の不具合は区別する。

### 13.5 四つの外殻への対応と再合流

対話相手と主人公は人物を表す語へ、環境は場所・物・出来事の語へ、相互関係は「友人」「所有」「待つ」などの関係を表す語へ圧縮できる。各外殻を同じ厚みで表現する必要はない。主人公のない状況では、プレイヤーを世界の外から操作する立場にしてもよい。

ここで得たいものは、どの要素が状況の成立を支え、何を失うと意味が変わるかという知見である。得られた依存関係や変化の規則を、対話型のコンテキスト設計へ戻すことができる。

この案の追加は、現在の開発を自動で切り替える指示ではない。小さな実験として選べる代替経路を、設計思想の中に保持する。
