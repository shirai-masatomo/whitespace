## 再現した残存課題

以下は修正済みではない。判定方式・ゲーム設計の次タスクとする。

| 入力・操作 | 現在の挙動 | 問題と次の判断 |
| --- | --- | --- |
| 大丈夫じゃない | reassurance、信頼+1 | 否定の範囲を扱わず「大丈夫」に一致する |
| ごめんとは思わない | apology、信頼+1 | 謝罪を否定しても謝罪になる |
| 知らないわけじゃない | rejection、緊張+2 | 二重否定を扱えない |
| お前の話を聞きたい | hostile、緊張+2 | 呼称だけで敵意とみなし、傾聴より優先する |
| 面倒を見たい | hostile、緊張+2 | 「面倒」の別の意味にも一致する |
| 私が悪かったけど、お前も悪い | hostile、緊張+2 | 複数意図を一つに潰す。優先順位の設計が必要 |
| ここにいるよ | reassurance、返答は「大丈夫って……」 | 入力していない言葉を相手が問い返す |
| 未分類の入力 | unknown、緊張+1 | システムの語彙不足がプレイヤーへの不利益になる |
| 謝罪などを繰り返す | 信頼を加算し続ける | 同じ発話の連打で成功できる。バランスは今回変更しない |

短語を今回そのまま採用した場合は「話せる範囲でいい」→command、「今来たばかり」→hostile等の誤検出が生じる。今回の保留により、その新規の誤検出は導入していない。

## 相談したい設計判断

1. **判断できない入力の扱い**: 推奨案は、否定・引用・複数意図で判断を保留した場合に緊張を加算せず、聞き返すこと。現在のunknownは緊張+1なので、導入には明示的なゲーム仕様変更が必要。全unknownを同じ扱いにするか、曖昧なケースだけ別結果にするかを決める。
2. **文脈に依存する表現**: 「話したくない」「放っておいて」を拒絶として罰するか。「許して」を謝罪に含めるか。呼称だけで敵意とする既存「お前」を維持するか。推奨は曖昧なものを保留したまま、具体的な場面で評価すること。
3. **次の試作の方向**: 「宥めよ」の完成を優先するか、作品に依存しない言語判定の実験へ広げるか。直近の会話に沿う推奨は、比較用の入力事例を共通化した小さな実験。ただしEmbedding・LLMの導入や外部API利用はまだ決定・実装していない。
