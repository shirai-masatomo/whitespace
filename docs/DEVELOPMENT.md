# 開発・検証の手順

普段の起動は [README](../README.md)、未解決事項と直近の確認は [STATUS](STATUS.md)。ここは実装を変更する人向けの仕様・手順の正本です。

## 確認する

アプリフォルダで実行します。

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

文書のリンク確認は `node scripts/check-doc-links.mjs`。言語評価・ゲーム進行・モデル契約/API・人物表示/資源解放・場面の知識/同意/物の更新をテストします。画面を変えたらブラウザでも確認。文書だけならリンク・図・記述と実装の整合を確認し、無関係なテストの繰り返しは不要です。

Three.jsの描画処理を変えたら、HMRに古いインスタンスが残り得るため再読込します。開発パネルで表示だけの信頼/緊張、短い反応、代替表示、WebGL接続喪失と再試行を確認できます。productionでは内部パネルを出しません。モデルAPIはVite dev/previewに付属し、distだけの静的配信には含まれません。

## 処理の境界

| 処理 | 実装 |
| --- | --- |
| 画面切替 | Workspace → App / Comparison / CoffeeScene |
| ゲームの言語評価 | lib/intentMatcher.js。入力・直近最大5件の履歴・状態を受け、intent/disposition/matches/reason等を返す。辞書版は入力のみ使用 |
| ゲームの進行と返答 | lib/gameEngine.js（数値・反復・回復・終了）→ lib/responses.js（返答・振り返り） |
| コーヒーの更新 | lib/coffeeScene.js のstepCoffeeSceneが唯一の境界。lib/coffeeRules.jsの優先順付き条件・発話・効果を適用 |
| コーヒーの表示 | coffeePresentation（入口文）/ CoffeeScene（操作・台詞・履歴）/ CoffeeTable（机上）/ coffeeCharacter（胸像への値） |
| モデル | lib/coffeeLanguage.js / modelContract.jsで契約、server/coffeeModel.js / localModel.jsでローカル通信。実測条件はLOCAL_MODEL |
| 人物 | Character → lib/characterState.js（姿勢と一時反応）→ character/createCharacterRenderer.js。造形はcreateBust、解放はdisposeScene |

状態から表示を決める処理はThree.jsを知らず、LLMの起動にも依存しません。描画のRAF・監視・共有資源を画面切替で解放し、非表示時は休止。3D失敗時はSVGと説明へ切替え、現在の会話を保って再試行できます。動き軽減は静的姿勢を残して呼吸・揺れ・面・一時反応を抑えます。手動設定は再挑戦で保持、画面切替では初期化。

## コーヒーで守る区別

- 原因などの世界の事実と、主人公が実際に見聞きした知識は別。開示は台詞内の根拠付きで記録し、再質問で知識を消さない。
- 援助辞退、事前確認要求、受取同意は別の記憶。同意・所持が揃って初めて紙が移る。離れると未実行の同意を解除し、再び話す/渡そうとすると近くへ戻る。
- 発話と実際の動作は別。紙が相手の手元→観察で拭く→使用済み。提案だけで物を動かさず、ト書きも実際の更新に対応させる。
- 謝罪はCの初回だけ、距離取りは初回だけ落ち着く。知識・記憶・落ち着かなさは後の反応/表示に影響。再開始・条件/画面切替で初期化。
- 通常候補の表示と処理できる行為は別。紙の所持がなければ「渡す」を無効にする。検証欄だけは全9操作を試せる。
- 自由入力は既知情報と直近履歴だけから解釈し、形式を検証し、ユーザー確認後に同じ更新境界へ渡す。モデルは世界や数値を書き換えない。

## 詳細を必要時だけ出力する

```powershell
node scripts/export-coffee-state.mjs
```

全状態・全9操作の遷移をリポジトリの `.tmp-docs/coffee-states.json` に出力します。Git対象外で、人向け図は上書きしません。状態を同一視するキーはsceneSnapshot（将来に影響する四つの外殻と記憶）。履歴長や直近の台詞は含めません。coffeeGraph.test.jsは同じ探索で知識・所有・同意・出来事の不変条件を検証します。全列挙は全台詞の自然さを保証しません。

人向け図は [COFFEE_FLOW](COFFEE_FLOW.md)を直接編集します。少数の代表分岐を線でつなぎ、分岐を比較できることを優先。要約・省略範囲を明示し、改善案を現行の流れへ混ぜません。大量の個別Markdownを生成するスクリプトは廃止しました。

図の画像化は `node scripts/prepare-coffee-diagrams.mjs` でMermaid部分を `.tmp-docs/` へ抽出し、Mermaid CLIで描画します。READMEやアプリの依存を増やさない任意の文書用手順です。

```powershell
node scripts/prepare-coffee-diagrams.mjs
npx.cmd --yes @mermaid-js/mermaid-cli@11.17.0 -i ../../.tmp-docs/coffee-1.mmd -o ../../docs/images/coffee-tissue.png -w 1600 -b white
```

辞書のレビュー一覧だけは採否・出典確認のため常設します。`npm.cmd run review:intents` でJSONから更新。個別の理由・出典・利用条件を落とさず、保留語を無条件採用しないこと。

## 会話ゲームと辞書の現在の規則

対象は `prototypes/001-nadameyo`（Vite + React）。5回の発言で相手の信頼を得る。初期値は信頼0、緊張2、発言数5。

| 評価・行動 | 信頼 | 緊張 | 発言数 |
| --- | ---: | ---: | ---: |
| 謝罪・傾聴・安心 | +1 | 0 | -1 |
| 命令 | 0 | +1 | -1 |
| 拒絶・敵意 | 0 | +2 | -1 |
| 未分類・判断保留 | 0 | 0 | -1 |
| 同じ肯定的な文を再送 | 0 | 0 | -1 |
| 緊張を上げた発言の直後に、初めて使う謝罪文 | +1 | -1 | -1 |

反復は、この会話中の全発言についてNFKC・小文字化・空白/句読点除去後に比較する。言い換えた同義文までは同じ文とみなさない。反復した命令・敵意等の緊張増加は継続する。

空白だけの入力と終了後の入力は無視する。入力欄は最大80文字。成功・失敗判定は「緊張5以上→失敗」「信頼4以上→成功」「発言数0→失敗」の順。同時に最後の発言で信頼4なら成功。数値は信頼0〜4、緊張0〜5に収める。再挑戦は履歴を含め全状態を初期化する。

未分類・判断保留では自然に聞き返し、最終発言では会話終了の返答を優先する。理解できなかった入力をプレイヤーの悪意とみなさない。

## 判定の対応範囲

88件採用・43件保留・13件除外・未レビュー0件。全144件の採否理由と外部辞書の出典は保持する。「話してください」は傾聴。

- 採用表現を正規化した部分一致で照合する。同じ位置を覆う長い採用表現は短い表現より優先する。
- 保留・未レビュー表現が残れば判断保留。「面倒くさい」「きっと大丈夫」を短い採用語だけで断定しない。
- 除外候補自体は照合に使わない。保留語より長い採用表現「話せる範囲でいい」は傾聴になる。
- 肯定カテゴリだけが混在する場合は傾聴→謝罪→安心の順で代表を1つ選び、信頼加点は最大1。肯定と敵意・拒絶・命令などが混在すれば保留する。
- 正規化後2文字以下の保留・未レビュー語は、空白・句読点で区切った区間全体との一致だけに限定する。「ばかり」「バカンス」内の短語では保留しない。「ばか」「ごめん、ばか」は保留。形態素解析ではないため、区切りなしの「ごめんばか」などは検出対象外。長い保留語は従来の部分一致を維持。
- 限定した否定形：「大丈夫じゃ/では/でもない」「大丈夫じゃ/では/でもありません」「大丈夫とは思わない/言えない」「ごめんとは思わない/と思ってない」等を保留。正規表現の具体的な範囲は `intentMatcher.js` に集約する。
- 「一人じゃない」「無理しなくていい」「話さなくてもいい」「責めないよ」は安心。「ない」だけでは除外しない。
- 「知らないわけじゃない」等の二重否定、「面倒を見たい」、「お前の話」、かぎ括弧の直後に「と言/って言/と聞/と書…」などが続く伝聞を限定的に保留する。

一般的な日本語の構文・否定範囲・主語・皮肉は解析しない。例えば「大丈夫なわけがない」「ごめんと言うつもりはない」、かぎ括弧のない伝聞等は未対応で誤判定し得る。長い保留語の部分一致も保守的すぎる場合がある。この小実装で日本語全般を理解できるとは扱わない。



## 比較ラボの制御

入力は280文字、Enterは改行。辞書の結果を先に出し、モデルは逐次実行する。120秒で待機を終了し、形式不正なら次へ進むが、通信失敗・タイムアウト・中止では後続を未実行にする。4項目の応答形式と入力内の根拠を検証する。辞書はブラウザ内、モデルはAPIの処理時間なので測定範囲は異なる。画面切替で結果を初期化し、明示的なJSON保存以外に会話を永続保存しない。
