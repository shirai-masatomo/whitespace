# コーヒー場面実験（2026-09-10）

## 検証する主眼と範囲

[設計思想書](DESIGN_PHILOSOPHY.md) の「同じ発言の意味が人物・環境・主人公・関係で変わる」を、一つの固定場面で検証する。`#coffee` はゲーム/比較ラボから開ける独立画面。得点、5ターン、勝敗は持ち込まない。ランダム生成、MBTI、他場面、言語ジェンガは作らない。

| 条件 | 関係・原因 | 相手の希望 | 主人公の初期情報 |
| --- | --- | --- | --- |
| A | 友人・相手が自分でこぼした | 手短なティッシュの援助 | 濡れた机と倒れたカップを見た。事故の瞬間は見ていない |
| B | 他人・相手が自分でこぼした | 人目を集めず自分で拭きたい | 同上。近くの席の客である |
| C | 友人・主人公がぶつかった | 手短なティッシュの援助 | 双方が事故の原因を知る |

A/Bの違いには間柄と望む接し方の両方がある。この3条件だけで、それぞれの因果を独立して測れたとは扱わない。次は一条件ずつ変える比較が有力。

## 小さな状態と更新規則

- 対話相手：落ち着かなさ0〜5、困り事（濡れた机/解消）、希望（手短/静か）。数値は胸像の肩・動きに接続するためだけに用いる。
- 環境：コーヒーをこぼした出来事、机の濡れ、ティッシュの所在（主人公/相手/使用済み）。持ち物はこの所在から表示し、二重管理しない。
- 主人公：役割、見た物、知っている原因・けがの有無・相手の希望、実行可能な3行動。
- 相互関係：友人/他人、実際の原因、共有済み項目、援助同意、謝罪済み、拒否履歴。

事実は `relationship.cause`、主人公の認識は `player.knowledge.cause`。A/Bでは初期null。開示すると知識と共有済み項目を更新。通常表示は既知情報だけを読み、開発表示は未開示の事実を明記して別枠に置く。「開始時に見たこと」は過去の説明として折りたたみ、現在の物の状態と混同しない。

| 入力 | 条件に応じる反応・更新 |
| --- | --- |
| どうしたの？ | 原因と希望を共有。再質問は「さっきのこと」と返し知識を保持 |
| 大丈夫？ | けがなしと希望を共有。机は濡れたまま |
| ごめん | A/Bは責任の前提を訂正し原因を共有。Cは初回のみ謝罪を受け止め落ち着かなさ-1 |
| あなたの味方だ | 感謝/距離の希望を説明。抽象的支持だけでは片付かない |
| 手伝おうか？ | A/Cはティッシュ受け取りに同意。Bは漠然とした手伝いを断り、静かな援助なら検討すると説明 |
| ティッシュいる？ | 机が濡れ、主人公が所持していればA/B/Cとも具体的な受け取りに同意 |
| ティッシュを渡す | 同意+所持がある場合だけ相手へ移動。まだ机は濡れたまま。同意なし/拒否後は確認を求め、物は動かさない |
| そっとしておく | 未実行の同意を解除、初回だけ少し落ち着く。知識や物は消さない |
| 様子を見る | 相手がティッシュを持つ場合に、相手が実際に拭く。机が乾きティッシュは使用済みへ。それ以外は観察 |

「様子を見る」はこの試作に限定した時間経過の操作。渡す→拭くを一つの発言で飛ばさないため採用した。質問を経ずに、見えている濡れた机から直接ティッシュを提案してよい。乾いた後も会話できる。再開始・条件切替・画面切替で全状態と自由入力の結果を初期化する。

## 境界と表示

`coffeeScene.js` の `stepCoffeeScene(state, interpretation, input)` が唯一の状態更新境界。選択肢も検証済みモデル解釈も同じ関数へ渡す。返答・理由・変更前後・差分を履歴に記録し、未知の行為では事実を更新しない。今回のテンプレートは同モジュールにまとめ、まだ大きなルール基盤には分けない。

`coffeeLanguage.js` はモデル契約と既知情報の抽出、`server/coffeeModel.js` はローカル通信、`CoffeeScene.jsx` は入力・待機・確認・表示を担当。`coffeeCharacter.js` が既存胸像への表示値を作り、`Character` の表示専用入力を使う。架空のゲーム得点は作らない。既存ゲームの表示経路は保持する。画面切替/条件変更で既存の描画破棄処理が働く。

## 自由入力の実測と限界

既存 **Ollama 0.33.3 / qwen3.5:2b-q4_K_M（約1.945GB）** を使用。新モデル・依存の追加取得なし。127.0.0.1:11435のみ、クラウド無効。今回の起動ログでもRTX4070 SUPER/CUDA利用を確認。環境の詳細は [LOCAL_MODEL](LOCAL_MODEL.md)。

入力280文字、主人公の既知情報、直近5往復だけを渡す。未開示の希望・原因を送らない。出力はstatus/act/target/evidence/reasonの5項目。型・許可行為と対象・保留の整合・入力内に実在する根拠を検証する。モデルは物/数値を指定できない。温度0、seed42、think=false、4096 context、最大300生成トークン。

解釈が有効でもプレイヤーが「この解釈で進める」を押すまで状態は変えない。未対応/保留は聞き返しとして残せる。不正形式は適用しない。45秒サーバータイムアウト・50秒ブラウザ待機上限・中止・通信失敗を扱い、選択肢は常に使える。条件変更や選択肢操作で進行中の推論を中止し、遅れて来た結果を捨てる。Enterは改行で、送信ボタンを使う。

生成した10例（実プレイヤー入力ではない）を2版のプロンプトで実測した。期待行為は暫定でモデルへ送っていない。

- [v1実測](experiments/coffee-language-2026-09-10.json)：最初の要求は45秒でタイムアウト。完了した9例中3例のみ形式有効。相手の同意の不明を「発言の意味が不明」と取り違え、保留と具体的対象を混在させた。
- v2では「実行可否でなく発言の行為を読む」と明示し、謝罪/保留の短い出力例を追加。[v2実測](experiments/coffee-language-v2-2026-09-10.json)：10例中9例形式有効、2例が謝罪、7例が保留、1例が形式不正。形式有効を意味正解と同一視しない。
- v2の有効9応答：中央値 **0.344秒**、範囲 **0.269〜8.148秒**。モデル読込欄は約1.5〜2.1msで、すでにロード済み。Cの8.148秒は外れ値として残す。コールド読み込みの完了時間は測れていない。
- A/Cの「ごめん」はモデルが同じapologizeを返し、アプリが責任の違いから別の反応を選べた。
- 「ティッシュ、使いますか？」「ティッシュを渡す」「さっき何があったって？」は過剰に保留。否定は肯定行為へ強制されなかったが理由は不適切。「店員を呼んで」も未対応と正しく区別できない。「ごめん、ティッシュいる？」は形式不正。

現状の自由入力は確認付き実験。選択肢の代替として安定した完成度ではない。次に試すなら、同意・実行可否と発言の解釈をさらに切り離した少数例と未使用の言い換えで比較する。今回の測定例への過適合に注意する。

## 実ブラウザと自動検証

- A/Cの謝罪、A/Bの援助の言い方、Bで拒否→無同意の受け渡し→具体的再提案→同意→受け渡し→観察による片付けを実操作。
- Aの情報開示と再質問、同意後の距離取り/再受け渡し、受け取り済みの心配/支持の返答を確認。再びティッシュを求める不整合を発見し、状態に合わせ修正して再確認。
- モデルC「ごめん」はブラウザで0.24秒。採用前の履歴0件、採用後の謝罪反応を確認。混在入力の形式エラーでも1件のまま維持。
- 推論中に条件を切り替え、古い解釈が新しい会話へ入らないことを確認。
- Ollamaを実際に停止。自由入力で接続エラー、再開始後も選択肢による援助同意が動作。
- 390×844指定（内容幅375px）で操作。clientWidth=scrollWidth=375、横はみ出しなし。胸像・返答・全9操作が見える位置へ操作後に移動するよう改善。確認後は幅指定を解除。
- 比較ラボで辞書「ごめん、話を聞くよ」→傾聴。既存ゲームで成功・失敗・再挑戦、場面への復帰で知識/物/履歴初期化を確認。
- ラボではcanvas0。画面/条件切替の3Dログでactive1→0、released17を確認。長時間GPUメモリ測定の代わりとは扱わない。
- 46テスト成功（既存33＋場面/契約/通信13）、lint・production build成功。3Dチャンク536.56kB警告は従来通り残る。
- 実IME・実スマートフォン・OSの動き軽減設定・長時間メモリ測定は今回未確認。モデルの意味精度、隠れた事情の推理、未知場面への一般化は未解決。

次の場面へ持ち出せそうなのは、事実と既知情報の分離、対象を限定した同意、行為解釈→規則による更新、変更根拠の履歴。ただし他場面への再利用はまだ実証していない。
