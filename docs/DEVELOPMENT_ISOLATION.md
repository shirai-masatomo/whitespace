# WhiteSpace — 開発・実行環境の隔離に関する必須規約

制定: 2026-10-20。ユーザーの必須指示を記録したもの。Ren'Pyに限らずWhiteSpaceの全ゲーム制作に適用する。

## 基本原則

**ゲームの開発・起動・テスト・ビルドにおいて、ユーザーが普段使用するWindows環境および既存プロジェクトに影響を与えてはならない。**

作業効率やテストの成功よりも、既存環境の保護を優先する。

## 1. 隔離環境での実行を義務化

- ゲームの起動・自動操作・GUIテストは、独立した隔離環境で実施する。
- Windows Sandbox、仮想マシン、または同等のファイルシステム・設定・プロセス隔離を備えた環境を使用する。
- 通常のWindowsデスクトップや、ユーザーが操作中のセッションでゲームを起動しない。
- 非表示起動、バックグラウンド実行、別Desktopへの表示切替だけでは完全な隔離と認めない。
- 実行に必要な素材・プログラムは隔離環境へコピーし、原本を保護する。
- 隔離環境からホストのユーザーフォルダへ書き込めない構成を原則とする。
- ネットワークアクセスは原則無効とし、必要な取得処理は事前承認を得て行う。

## 2. 既存環境への変更禁止

ユーザーの明示的な承認なしに、以下を行ってはならない。

- Windowsのシステム設定変更
- レジストリ変更
- グローバルな環境変数変更
- 既存アプリケーションのインストール・削除・更新
- GPUドライバーや共通ランタイムの変更
- Windowsサービスや常駐プロセスの登録
- スタートアップ設定変更
- 既存ゲームのセーブデータ・設定ファイルの変更
- WhiteSpaceの別プロジェクトへの変更
- ユーザーの既存作業プロセスの停止

必要なツールや依存ライブラリは、可能な限り隔離環境内に導入する。

## 3. Ren'Py固有の保護

- Ren'Py SDKは隔離環境内で実行する。
- Launcher、ゲーム本体、Lint、配布ビルドの起動確認も隔離環境内で実施する。
- Ren'Pyのセーブデータ、persistentデータ、ログ、キャッシュがホスト側のユーザープロファイルに保存されないようにする。
- テスト用セーブデータは製品用データと完全に分離する。
- 通常のWindows環境にゲームウィンドウを表示しない。
- 実行テスト後にテスト用プロセスが残存していないことを確認する。

## 4. テスト・ビルドの運用

- ソースコードの編集と、ゲームの実行・検証を明確に分離する。
- 静的解析は可能な範囲で実施する。
- GUIテストが必要な場合のみ、事前に隔離状態を確認して起動する。
- スクリーンショットは隔離環境内のゲーム画面だけを取得する。
- ビルド成果物は専用ディレクトリへ出力する。
- テスト終了後に不要な一時ファイルとプロセスを整理する。
- ユーザーのデスクトップ、タスクバー、作業中のウィンドウへ干渉しない。

## 5. 隔離環境が使用できない場合

**隔離を確認できない状態でのゲーム起動は禁止する。**

その場合は、実施可能な静的検証やコードレビューのみを行い、GUI動作確認は「未実施」として報告する。
検証を完了させるために、安全規約を緩和してはならない。
ホスト環境での実行が不可欠な場合は、理由と影響範囲を提示し、ユーザーの明示的な承認を得るまで実行しない。

## 6. 完了報告

Codexは各工程の終了時に以下を報告する。

1. 使用した隔離方式
2. 隔離環境内で実行したテスト
3. ホスト側に行った変更の有無と内容
4. 残存プロセス・一時ファイルの確認結果
5. 隔離上の制限によって未検証となった事項

確認できない事項を「影響なし」「完全に安全」と断定しない。

## 最優先事項

本規約は、個別のゲーム制作指示よりも優先する。
**安全に実行できない作業は、実行しない。**
この原則を守った上で、Codexが自律的に開発・検証を進めること。

## 実務上の適用

- Git worktreeは既存変更を保全するためのソース分離であり、実行環境の隔離ではない。
- SDKを展開するだけならソース準備として扱えるが、実行ファイルやSDK内Pythonをホストで起動しない。
- SDKがロードする初期化処理には副作用があり得る。CLI、Lint、ビルドも例外としない。
- VMの存在・停止状態・ネットワーク・共有ディレクトリの権限を確認してから、ゲスト内コピーで実行する。
- GUI自動操作の対象は隔離環境の画面に限定する。ユーザーの物理Esc等による停止操作を尊重する。
- 環境の導入・OS機能の有効化が必要なら、実施内容と影響範囲を示して承認を求める。勝手に有効化しない。
- テスト用の専用プロファイルをゲスト内に用意し、配布物には含めない。製品の保存先設定をテストの都合で変更しない。
- 出力をホストに持ち帰る必要がある場合、専用出力先・共有方式・アクセス範囲を事前に決める。ユーザーフォルダ全体を共有しない。
- 同一ホストでも別ユーザー・別Desktop・コンテナという名称だけで合格としない。必要な隔離の実態を確認する。
