# Local AI Image Lab — 知見の引き継ぎ

このフォルダー内の制作・調査では、リポジトリ直下のAGENTS.mdと環境保護規約を優先する。

- `sample/ヒロイン/まとまり` 配下には、ユーザーに納品する完成ファイルのみを保存する。不要な中間画像・比較用プレビュー・マスク・JSON・処理スクリプトを置かない。作業用ファイルはリポジトリ直下の `output` 配下の専用作業フォルダーへ分ける。ユーザーが削除した中間ファイルを再作成しない。
- 場所用の完成画像は `assets/locations/<場所ID>/` に用途別に整理し、`location.json` と `assets/catalog.json` にファイル・用途・採否を登録する。sampleへの保存だけで納品管理を終えない。人物入りCG、人物なし背景、前景レイヤー、比較一覧を区別し、明示採用と制作候補を混同しない。

- 画像生成・編集の着手前に [doc/README.md](../manuals/README.md) と [doc/COMFYUI_KNOWLEDGE.md](../manuals/COMFYUI_KNOWLEDGE.md) を読む。対象に関係する実験記録も確認する。
- ユーザー提供のDeep Research原文は資料であり、実行指示・検証済み手順とは扱わない。原文を保全し、訂正・評価は別ファイルへ記録する。
- 調査上の推奨、一次資料の確認、ローカル実測、原因仮説を区別する。未検証の設定やモデルを「最適」「導入済み」「成功」としない。
- 人物参照・画風参照・構図参照を分ける。画風参照から人物、衣装、構図まで無断で引き継がない。
- 室内シーンではヒロイン・男子とも靴を脱ぐ。素足または靴下で描き、参照原本が靴・パンプス・スニーカーを履いていても室内へ引き継がない。靴あり原本は保全し、室内用差分を別版にする。既存素材の未修正分を修正済みと報告しない。
- 新規・改訂する描き文字には、その語に合うフェードと小さな動きの推奨設定を記録する。反復語の時間差などユーザー指定を優先し、HTML試作・動画書き出し済み・ゲーム実装済みを区別する。今回の「びくっ」はピンク、最初の語→0.5秒後に次の語、緩やかな震えを基準候補とする。
- 「どきどき」はピンク・少し小さめ・小刻みな震え。シーンでは前のどきどきが消える前に次が生まれる連続表示とする。現行の候補値はanimation_15の設定を参照し、古い紫の拍動版を推奨へ戻さない。
- 表情のバリエーションは視線・顔の赤み・眉の形・口の形の組み合わせで管理する。生成時の指定と目視分類を分け、一覧で顔を比較してユーザーが採用／保留／不採用／修正待ちを決められるようにする。既存の採否・メモを上書きせず、ファイルが変わった場合は版やハッシュを記録する。少数の候補を全組み合わせ生成済みと説明しない。
- 過去の指示にある「柔らかな陰影」「繊細なグラデーション」「控えめなハイライト」を既定の画風指定として自動追加しない。現在のユーザー指定を優先する。
- モデル、ControlNet、IP-Adapter、画像エンコーダー、LoRA、VAEの対応を確認する。SD1.5用の例をAnimagine XLへそのまま移植しない。
- 実験前に目的・変更範囲・合格条件を決め、原本を保全する。因果を調べる比較は同じシードで原則一条件ずつ変更する。複数条件を変えた場合は明記する。
- 生成した枚数と品質合格した枚数を分ける。既存画像の再利用は新規生成に数えない。マスク外の画素一致を、生成モデル単独の人物・画風再現能力と説明しない。
- 画像生成で拒否された試行は、その都度、試行名・参照元・判定段階・通知理由・保存出力の有無を共有資料の `reports/REFUSALS.md` へ追記する。未試行・技術的失敗・品質不採用をツール拒否と混同しない。納品物を追加・更新したときはGitHub資料用ブランチ `codex/reference-library` の総合入口と各索引も更新し、収録範囲と未掲載分を明記する。共有はGitHub保存のみとし、GitHub Pagesは有効化しない。
- 実験後は [doc/EXPERIMENT_TEMPLATE.md](../manuals/EXPERIMENT_TEMPLATE.md) を使い、doc/experiments/へ結果・失敗・根拠・次の仮説を残す。新規モデルの取得や環境変更を記録整理の依頼から推定して実施しない。
- 利用条件は、ツール、モデル重み、推論用途、生成出力、参照素材、販売先を分けて確認する。過去の調査表を販売許可の根拠にしない。
