# 恒常的な画面自己レビュー

工程1以降の背景・静止キャラ・配置・UI・短い効果表示の変更時に使用する。[画作り受入基準](dot/PHASE_01_VISUAL_TARGET.md)を補助する検証手順で、素材採否やゲーム仕様を変更しない。

## 判定を分ける

**A「描画成立」とB「画面の自然さ」は独立した必須条件。Aの合格からBの合格を推定しない。** 未確認は未確認、欠点は欠点として残す。座標・サイズ監査だけではBを合格にしない。

### A. 描画成立

- [ ] 実EXE、コミット、EXE/PCKのSHA、解像度、表示条件を記録した。
- [ ] 主人公・敵の全身と必要な余白が表示範囲内にあり、切れ・不意のクリップ・UIとの重なりがない。
- [ ] HP/SP・数値・ログ・ラベルが読め、有効／無効／フォーカスを見分けられる。
- [ ] 背景・人物の縦横比を保ち、過剰な拡縮・切抜き・変形で問題を隠していない。
- [ ] 状態エフェクト追加時も人物・足元・情報が読め、描画が戦闘乱数や保存状態を変えない。

### B. 画面の自然さ

- [ ] **接地**：左右の足・接触面が床に載る。透過キャンバス下端を足元と取り違えず、浮遊する敵は意図した浮き高さとして確認する。
- [ ] **連続床**：両者が同じ連続した床に立つ。崖断面・穴・水面・舞台の前縁が足元を横切らない。
- [ ] **前景余白**：人物の前後に立てる床があり、画面内に収まるだけの細い足場に見えない。障害物・門と輪郭が不自然に密着しない。
- [ ] **縮尺**：主人公・敵・門・石床の相対サイズが場の意図に合う。絶対寸法が未決なら、誤り／正解を断定せず違和感と比較を残す。
- [ ] **遠近**：床の奥行き・キャラの俯角・前後配置が共存する。位置を数pxずらしただけで視点を修正済みと扱わない。
- [ ] **向き**：左奥の敵と右手前の主人公の対戦方向が自然で、別カメラの素材を無理に並べた印象がない。
- [ ] 通常／ボス／変更対象の敵を同一EXE・同一解像度で比較し、PX参考との相違も記録した。反射・目地・照明など残る限界を隠していない。

## 証拠と反復

1. 変更前と変更後を同じ条件で並べ、A/Bをそれぞれ「合格・不合格・未確認」と理由付きで記録する。
2. 原画像と実EXE画面を確認する。寸法・座標・SHA監査は目視の補助とし、原画像だけでゲーム画面を合格にしない。
3. 少なくとも1回、自己レビュー→欠点／改善点の特定→修正→再撮影／再確認を行う。欠点がなければ追加変更を捏造せず、確認範囲を記録する。
4. `review/current/` の比較入口と [進捗](dot/PROGRESS.md)・[実装状態](IMPLEMENTATION_STATUS.md)へ証拠と残点を関連付ける。過去画像・ユーザー保存・使用中のEXEを破壊しない。
5. 通常デスクトップへの自動干渉をしない。隔離描画は許可済みの方法のみを使用し、拒否時に回避しない。アプリ内入力とOS物理入力の証拠を区別する。

記録欄：変更／実行コミット・SHA／解像度・入力方式／変更前後画像／A判定と根拠／B判定と根拠／欠点・修正・再確認／残る制約／素材の採否。
