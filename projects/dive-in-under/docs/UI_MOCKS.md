## 実装方法（工程1の推奨構成）

**参考画像全体をゲームに貼るのではなく、背景・キャラクター・動作UIを分ける**。現行0.2.0の背景はGodotスクリプトによる矩形の仮描画、戦闘キャラはコード内ドット配列の仮表示。**工程1の到達点はそこから一段進め、PX-01〜03の見た目に近いゲーム画面を作ること**。

- **背景**：2Dドット絵の洞窟／ボス戦等を独立した画像素材（PNG／WebP等）として配置。階層帯では画像を再利用・色替えしてよい。静止画で十分。
- **主人公・敵**：戦闘画面用の背景透過**静止スプライト1枚ずつ**。ユーザーが採用／不採用を確認する。採用後も今はモーションを作らない。
- **UI**：文字、HP/SP、ログ、装備・倉庫、ボタン類はGodot Controlで動作する部品。枠やアイコンの画像素材は再利用してよい。
- **演出は後工程**：待機／攻撃／被弾／歩行、表情差分、カットイン、背景アニメ等を工程1の必須にしない。

最初の10Fまで遊べることに加え、**実画面の背景・人物・UIが現行参考にどこまで近づいたかも工程1の受入基準**。[実装・検証の具体条件](dot/PHASE_01_VISUAL_TARGET.md)を参照。

## 今回変更する見た目

### 制作範囲の最新指示（2026-10-17追記）

効率を優先し、当面の主人公・敵・味方キャラクター素材は**戦闘画面用の静止画1枚のみ**。戦闘UIに配置した見え方・雰囲気で採用/不採用を先に確認し、採用後もしばらく静止画で使用する。待機/攻撃/被弾/歩行モーション、表情差分、カットイン、演出強化は今は作らない。工程1〜4はゲームループ・UI・戦闘成立を優先し、仲間システムを前倒ししない。[素材と実画面の確認入口](../review/current/README.md)を更新利用する。

- 青緑／黒の洞窟、滝、ロープ橋や木の足場、松明とランタンの暖色、真鍮の留め具、羊皮紙風のパネル、ドット絵の人物・アイテムが共通のデザイン参考。
- 高密度だが読みやすい日本語、統一されたアイコン、HP／SPバー、実数値、スクロールできるログ、選択中の明確な強調を優先。
- すべてのボタン・装備・所持品・ログは**実際に操作できるUI部品**として作る。画像をそのまま貼って擬似ボタンとしない。
- 個別キャラ・敵・アイテムの**正式な量産素材はまだ未承認**。ドットサイズや実装コストも検証する。

## 画像中の「仕様ではない要素」

| 画像の表現 | Dive In Underとしての正しい取扱い |
| --- | --- |
| 戦闘の「たたかう」「スキル」「アイテム」「にげる」 | **本作の戦闘は完全自動・素早さ順**。手動ターンコマンドは追加しない。必要ならログ・早送り・情報確認用UIに置き換える |
| 戦闘画像に人間3人がいる | **工程1〜4は主人公1人だけ**。仲間は工程5以降。工程1では敵と主人公1人の双方を表示する |
| 探索画像のミニマップ・横歩き・部屋接続 | **地下での基本入力は「潜る／地上へ戻る」**。マップ操作や横スクロール移動は実装しない。背景演出や簡略深度表示としてのみ参考 |
| 32階、Lv16、HP164、SP88等 | サンプルの数字。工程1の内容は1〜10Fと11F到達解放だけ。実際のデータを表示 |
| 器用さ、耐火・耐水・耐光・耐闇 | **器用さは追加する基本能力として採用済み**。8属性システムも導入予定だが、個々の耐性の数値・算出式や初期工程への実装は未決定。画像の値をコピーせず[COMBAT](COMBAT.md)に従う |
| ステータス画面の装備枠・選択アイテム | **人間の装備は右手・左手＋防具4＋装飾品5＝11枠**。[ITEMS](ITEMS.md)が正本。名称・効果・数値は仮 |
