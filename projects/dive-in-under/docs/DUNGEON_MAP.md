# ダンジョン階層分岐・探索ミニマップ（2026-10-19／確定方針）

[全体仕様](../SPEC.md) ｜ [階層台帳](FLOORS.md) ｜ [UI参考](UI_MOCKS.md) ｜ [アイテム](ITEMS.md) ｜ [仲間・スキル](ALLIES.md) / [SKILLS.md](SKILLS.md)

> **状態**：ユーザーの手描き構想に基づく**ゲーム仕様の採用**。ダンジョンの全ノード・具体的な分岐階／鍵アイテム／スキル／実装工程は未決定。**資料記載はGodot実装済みを意味しない**。既存の工程1の単独1〜10F攻略や帰還を、指示なく改変しない。

**名称の階層（2026-10-19採用）**：一つのダンジョン全体名 → 10F単位の **第N層域＋固有名** → 同じ層域内の **本洞／支洞＋個別ルート名**。[正式な命名規則](DUNGEON_NAMING.md)を参照。既存の例示名は確定していない。

## 1. あらかじめ決まった枝分かれ構造（確定）

- ダンジョンは階層が基本的に下へ続くが、**途中の所定階層から複数の進路に分岐する**。分岐構造は事前に設計・定義されたもので、潜行ごとのランダム生成ではない。
- **特定の階層で、指定アイテムを所持していること**が、所定の分岐へ入れる条件となる。アイテムがなければ、その分岐へ進めない。必要なアイテムID・判定対象の所持区分・消費の有無・アイテム取得後の再訪手順は未決定。
- 一本道の通常ルートも残す。分岐先は固有の階層ノードとして管理し、異なる枝を同じ表示階数に載せる場合でも**内部IDは別**にする。
- イメージ：1F → 2F → 3F → 4F（本線）。3Fから条件付きで脇道へ移り、脇道の先にも別の分岐が存在し得る。**この図はトポロジーの例であり、3Fでの分岐確定ではない**。
- 分岐の解放状態をUIに表示する方法（鍵付き表示／枝を隠す等）、分岐点での選択操作、分岐先からの合流や戻り方は未決定。選択可能な進路が複数あるときは、それを選べるUIが必要。単一進路では従来の「潜る」を維持する。

## 2. 階層ノードの種類（確定）

- 各階層ノードの主な内容／種別は、**BOSS・敵（戦闘）・宝・イベント**のいずれかとして**事前に決めておく**。潜行時に次ノードの種別自体を抽選しない。
- 各ノードの種類は**通常のミニマップでは伏せる**。事前定義されたノードを見ても、次がBOSSか敵か宝かイベントかは通常は分からない。
- **一部の情報察知系スキルを持った味方がパーティにいる場合、次ノードの種類が分かる**。判明するのは種別であり、敵ID・宝の中身・イベント結末などの詳細を無条件に開示するわけではない。
- そのスキルを持つ仲間の具体名／対象範囲・表示アイコンは後決め。工程1〜4は主人公単独、味方の加入と仲間固有スキルによる情報開示は**工程5以降の実装検討**とする。仲間不在の既存攻略を阻害しない。

## 3. 探索画面のミニマップと全景（確定）

- 探索画面には**階層の接続関係を示す小さなミニマップ**を常時表示する。
- ミニマップの基本表示範囲は、**前階層・現在階層・次階層**。分岐点にいる場合は、そこから伸びる複数の次階層・接続線も見せる。
- **現在位置を強調表示**し、通ってきた経路と、今後の枝の区別を付ける。階数／ノード名の表示は実際に確定したルート定義に従う。
- **ミニマップをクリックすると、分岐を含む階層構造の全景を表示できる**。ユーザー文の「前景」はここでは全景（拡大マップ）の意味として扱い、最終的な開閉動作・ズーム／スクロールはUI実装時に確定する。
- **全景表示でも未判明のノード種別は隠す**。マップを開くだけでBOSS／敵／宝／イベントが分からないという原則は維持。情報察知スキルのある味方がいる場合のみ、定められた範囲で表示する。
- マップは**階層構造の可視化UI**であり、マップをクリックしてキャラクターを歩かせる方式や、自由なフィールド移動を導入するものではない。基本の「潜る／地上に戻る」と両立する。

## 4. データとして必要な項目（設計案・実装前に確定）

| 項目 | 用途 |
| --- | --- |
| `node_id` | 固有の階層ノードID（分岐ルート同士で重複しない） |
| `display_floor` | プレイヤー向けの階数表記 |
| `next_node_ids` | 接続先（通常1件、分岐点では複数） |
| `previous_node_ids` | 接続元（全景・戻り処理のため） |
| `node_type` | BOSS / ENEMY / TREASURE / EVENT。事前定義し探索中に抽選しない |
| `unlock_item_id` | 分岐進路への進入を許可する鍵アイテムID（不要なら空） |
| `reveal_requirement` | ノード種別を見抜けるスキル・条件（詳細未定） |
| `visited` / `current_node_id` | 訪問済み・現在位置をセーブするための状態 |

注：これは**実装データ項目の候補**。名前や保存形式を今ここで固定するものではない。鍵アイテムの具体例や分岐位置、探索に伴う種別の変更例は勝手に創作しない。

## 5. 既存仕様・工程との整合／未決事項

- [FLOORS.md](FLOORS.md) の「戦闘70%／宝20%／イベント10%」等は**旧・同一階層での遭遇種別抽選案**。今回確定した**ノード種別の事前固定**と競合するため、新方式を優先。移行まで表を資料として残すが、**種別を抽選し続ける根拠にはしない**。
- **敵ノード内の敵種・Lv、宝ノード内の品目、イベントノード内の内容の抽選**は、別途定義済みの条件付き抽選を再利用できる（詳細や残す抽選は後決め）。固定するのは少なくとも**ノードの基本種別**。
- 既存の**10F固定ボス、11F到達によるチェックポイント、主人公単独1〜10F攻略**は、具体的な分岐台帳を採用するまでは変更しない。枝の追加位置・ボス数・チェックポイントとの関係は後決め。
- 未決：どの階にどの枝を置くか、鍵アイテムのIDと入手ルート、所持判定のタイミングと消費、再訪・合流、未知／ロック中の枝の見せ方、情報察知スキルの効果範囲、工程への組込み時期。
- **制作境界**：今回は**設計仕様のみ**。ゲームコード・確率テーブル・セーブ形式・EXE・現在進行中の工程1を変更しない。実装時に機能／画面テストとセーブ互換を別途確認する。
