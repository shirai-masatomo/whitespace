# 工程3 — 装備11枠・耐久・キャラクター成長・経済

[全体仕様](../../SPEC.md) ｜ [アイテム台帳](../ITEMS.md) ｜ [戦闘補正](../COMBAT.md) ｜ [敵の報酬](../ENEMIES.md) ｜ [工程表](README.md)

## 目標

「どのアイテムを持ち帰るか」「何を装備するか」「誰を育てるか」が10F攻略に影響するようにする。工程1〜2の町・戦闘・セーブは維持し、**敵・味方の基礎値とレベル補正をゲームとシミュレーターで共通化**する。

## Codex実装内容

- **人間の装備11枠**：右手・左手（武器または盾）、頭・上半身・下半身・足、首・耳・目・指・腕。装備品を個体別に扱い、着脱・比較・装備によるATK/DEF/SPD等の反映、同じ1品を複数人が同時に装備できない保証を作る。
- **耐久**：耐久減少で能力低下、0で破損マーク・効果0、修復方法あり。何が耐久を減らすかの細部は仮設定し、戦闘後の消耗と管理UIをテストする。破損後でも装備ID・現在耐久値が失われない。
- **収納**：所持品／倉庫の預入・取出・整理、装備中アイテムの管理、支給品は倉庫へ保存できない検証。容量・持ち物ロスト・修理費用の**未決定値は可変で仮**。
- **経験値・Gold**：敵の基礎EXP/Goldを敵Lvで補正。レベル成長の曲線とSP上限、仲間の経験値分配は最小限の仮ルールとして実装。敵の強さ・報酬を階層で二重補正しない。
- **支給所**：初期版を設け、支給品は倉庫へ保存不可。出発・帰還・死亡時の持越しを明確に処理する。
- 装備細則（両手持ち、二刀流、両盾）はまだ正式ルールがない。まず**各手に片手武器または盾を1つ装備可能**な構造を採用し、追加制約は仮でバランス比較。未指定の組合せを黙って恒久禁止しない。
- UI：人間3名の装備を素早く切替、装備前後の性能差、破損・修理・持込品の状態を確認できる。画像の27部位という旧見積は、最新は**3人×11部位＝最大33枠**。

## 受入条件

- [ ] 11枠の装備・収納・付け替えで所有アイテムが消失・重複しない。
- [ ] 装備耐久低下→性能低下→0で無効→修理で復帰が、UI・戦闘・セーブで一致。
- [ ] 使える支給品を倉庫へ入れる操作は拒否され、失効・出発処理が正しい。
- [ ] 敵Lvと味方Lvを変えた際の強さ・EXP/Gold・SPが資料の仮式と整合する。バランス調整したら資料も同期。
- [ ] 1〜10Fの連続探索シミュレーションで装備前後・レベル差・損耗・報酬の比較を保存。
- [ ] Windows EXE／倉庫と装備画面の実写／自動テストとレビューを報告。

**対象外**：高級な装備合成・オンライン取引・大量素材・スキルの高度な自動選択（工程5）。
