# 工程5 — 仲間・配下のパーティ編成と死亡（旧工程2）

[工程表](README.md) ｜ [工程1](PHASE_01.md) ｜ [工程4](PHASE_04.md) ｜ [仲間台帳](../ALLIES.md) ｜ [全体仕様](../../SPEC.md)

## 目的

**工程1〜4で遊べる主人公1人のゲームへ、ここで初めて仲間システムを追加する**。人間3名（主人公＋人間2名）と各人間に配下1体（動物・魔物、合計最大3体）、**最大6体**。主人公単独の既存セーブ・難易度・操作フローを壊さない。

## Codexへ委任する範囲

- 種族ID／個体ID／人間の指揮者IDを分離。編成／控え／Lv・EXP／HP・SP／人間の装備・スキルと動物・魔物の装備不可状態を管理。**人間最大3人、配下最大3体、各人間に配下1体まで**をデータ・UI両方で保証。
- 主人公にも配下を付けられる。指揮者不在・死亡・控え移動で配下がどうなるかはまだ確定していないので、**安全な仮ルール**として保存・UI・テストに明示し、後で変更可能とする。
- **初回死亡後に黄金像が怪しく光り、犬が仲間になる演出**をここで導入する。**既存セーブ移行が必須**：工程1〜4ですでに初回死亡を終えたセーブでも、犬加入済みフラグが未設定なら、次の適切な町到着時に**一度だけ**発動する。ロードや再死亡で重複付与しない。
- **黄金像の動物・魔物ガチャ排出をここで解放**し、工程3のアイテム／装備だけの暫定排出を完成形へ移行する。人間はガチャから出さない。到達階層の排出候補と継続ルールはSHRINEの正本を尊重。
- 人間仲間は**ゲーム開始時には与えない**。加入の時期・人物像を正式決定しないまま増やさず、少なくとも一人の加入導線を仮実装し、最大3人編成テストではテストデータを使ってよい。EV03の解放が候補。
- **敵・味方の複数体戦闘**。既存のSPD順／SP／状態異常／自動スキル構成を人間・動物／魔物にも適用。配下の独立手番／指揮者への援護は未決なので比較しやすい構成とし、まず一方を仮採用して根拠を記録。
- 複数敵の編成・ボス難易度を新しい最大6体パーティに見合うよう調整。敵全体を無条件に強くして**ソロ1〜10Fの既存攻略を壊さない**。
- **仲間HP0は即死亡、原則永久離脱**。帰還する特性は例外として扱う。死亡時の所持・装備・関係値フラグは整合させる。主人公死亡による町帰還の特例は残す。
- **友好度・忠実度は保存用の構造のみ用意**。戦闘中の連携・忠実度効果は工程6まで作らない。

## 完了条件

- [ ] 人間3＋配下3の上限と、各人間1体までの指揮者の紐づけが正しい。
- [ ] 初回探索は単独で始まり、犬の加入は初回死亡後に1度だけ。**工程1〜4のセーブからアップデートしても詰まらない**。
- [ ] 人間・動物・魔物の加入／離脱／永久死亡／配下移動がセーブ・ロードで一致する。
- [ ] 1体／3体／6体の編成と複数敵のSPD順・スキル・SP・状態異常が正常に動く。
- [ ] ソロで10Fまで遊べる従来ループを維持。仲間あり・なしのヘッドレス比較を報告する。
- [ ] 編成UIの実画面、Windows ZIP、CIと自己レビュー・改善を確認できる。

**対象外**：友好度連携・忠実度による戦闘補正・隊列、町の全面改修、20F以降。旧工程2の番号・完了条件は再利用せず、本工程5が唯一の正本。
