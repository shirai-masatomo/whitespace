## 1. 背景・キャラ・UIを分離した構成（推奨）

| 層 | 工程1の作り方 | やってはいけないこと |
| --- | --- | --- |
| **背景** | 独立した**2Dピクセル背景画像**（PNG/WebP等）をGodotのTextureRect/Sprite2D等で表示。遠景・前景は必要なら別画像レイヤー。複数階層で再利用してよい | **参考UI画面を丸ごと背景に貼って、描き込まれた文字やUI枠を再利用すること** |
| **人物・敵** | 背景透過の**戦闘画面用静止スプライト**を個別素材として表示。主人公・敵のサイズ・接地・向きを統一 | 動画、待機／攻撃／被弾／歩行モーション、表情差分を制作すること |
| **インタラクティブUI** | GodotのControl、Button、Label、ProgressBar、Container等の部品で入力・文言・状態を制御。枠・アイコンは再利用可能な画像素材や9-sliceパネル | 画像の上に不可視のボタンを置いて擬似的に「動くUI」とすること |
| **演出** | 基本ログ・勝敗表示に加え、**毒・暗闇・麻痺・防御態勢の短いエフェクト、状態アイコン、解除ログ** | キャラクターモーション、大型カットイン・背景アニメへ先に工数を割くこと |

- 素材の権利・再利用・サイズを管理する。生成画像を利用する場合も、背景・人物・UI枠を**別レイヤーとして制作・書き出し**、ドットが潰れない倍率・フィルタ設定を採用。最初は**静止背景でよい**。
- 洞窟の見た目は、低階層／中層／深層／10Fボス戦で**明るさ・地形・色味・構図が変わる程度の背景バリエーション**を目指す。**各階専用の背景10枚は不要**。一種類の背景を使い回す場合も、探索の深度が視覚的に分かる補助表現を付ける。
- 町・倉庫／死亡結果は既存のゲームループを使い、同じドット調のフレーム・素材に統一する。町の建物を3Dで制作する必要はない。

## 3. キャラクター素材の承認フロー

1. まず主人公＋代表的な敵1〜2体（できれば10Fボス候補も）について**戦闘用静止画のみ**生成し、実際の戦闘UIに配置して**採用／不採用を判断できる画像比較**を用意する。
2. 採用された絵柄を基準に、必要な敵（工程1のE01〜E05・B10）へ静止画を拡張する。**仮のコード描画は採用判断前の一時素材**と明記する。未採用なら正式素材として登録しない。
3. **採用された静止画も工程1では動かさない**。待機・攻撃・被弾・歩行、表情差分、カットイン、豪華なエフェクトは後工程へ。ただし**先行状態の小さな発光・色変化・アイコン・数値表示**は工程1に含める。
4. **人間が必要な判断は素材の採否と「参考UIに近いか」の節目レビューだけ**。レビュー待ちでもゲームループ／テストなど独立した作業は継続し、不要な逐次承認を求めない。

## 4. 受入条件（工程1の通常要件に追加）

- [ ] **PX-01／PX-02／PX-03と実際のEXE画面を並べて比較**し、背景・人物・パネル・文字・情報配置のうち、実装済み／未実装を可視化できる。
- [ ] 探索・戦闘の主背景が、単純な矩形のコード仮描画から、**独立した2Dドット背景素材**を使う構成へ移行している。少なくとも複数の階層帯とボスで見た目の差が分かる。
- [ ] 主人公と工程1の敵・10Fボスが**静止ビジュアルとして戦闘画面に表示**される。演出を増やす前に、採用判断用の比較資料が揃う。
- [ ] UIの文字・値・枠・アイテム・ボタンはゲームの実データに同期し、マウス／キーボードで操作できる。1280×720など主要なWindows解像度で文字切れ・重なりがない。
- [ ] 先行する**毒・暗闇・麻痺・防御態勢の付与・継続・解除と短いエフェクト**を実EXE上で確認できる。キャラ自体のモーションは不要。
- [ ] **主人公1人で**初回から帰還または自然死亡**→町→再探索→10Fボス突破を実演／再現**し、セーブ・ロードとヘッドレス比較の証拠を示す。
- [ ] Windows EXE+データZIP、タイトル／探索／戦闘／町・倉庫／装備／死亡／10Fの実画面、テストログ、未承認素材一覧をレビュー入口から確認できる。
- [ ] **工程1を「見た目は後で」として完了扱いにしない**。ただし商用品質の全アニメや、モックの細かな美術表現の完全一致までは要求しない。採用未決の素材は明示する。

青い地下滝の戦闘背景は**1〜10F共通**（10Fの専用ボス背景は維持可能）。**1〜5Fは既存のE01〜E03、6〜9Fは水辺の新3種E06〜E08を中心**に見せる。新敵は濡れ岩ガニ・洞窟カエル・水棲トカゲの**静止画候補を各1枚だけ制作**し、現行の斜め戦闘場へ配置して**人間に採用／不採用を確認**。背景や採用済みキャラの再生成・モーション追加は不要。[エリア資料](../BIOME_01_10F.md)を参照。

## 継続する自己レビュー

画面を変更するたびに [恒常的画面自己レビュー](../VISUAL_SELF_REVIEW.md) の「描画成立」と「画面の自然さ」を独立判定する。全身が表示範囲内に入ることだけでは、接地・連続床・前景余白・縮尺・遠近・向きの合格を意味しない。旧ボス床面で見逃した欠点と修正前後の証拠を手順に反映する。
