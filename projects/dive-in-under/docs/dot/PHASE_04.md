# 工程4 — 階層データ・イベント選択肢・黄金像と戦利品

[階層出現率](../FLOORS.md) ｜ [敵・ドロップ](../ENEMIES.md) ｜ [イベント](../EVENTS.md) ｜ [黄金像](../SHRINE.md) ｜ [工程表](README.md)

## 目標

ランダムな遭遇と報酬を**IDで管理できる完成度**にする。階層を潜るたび「敵／宝／イベント」が変わり、イベント選択がゲーム状態に影響し、黄金像の到達深度別ガチャを使える。

## Codex実装内容

- 階層ごとに **遭遇種別 → 敵種の条件付き出現率 → 敵Lv抽選**、宝箱の場合は独立したアイテム抽選。**10Fは固定ボス**。倍率／抽選率は資料に基づく暫定値。
- **敵撃破時のドロップは敵IDごとの独立判定**。同じアイテムが宝箱と敵ドロップで入手できても区別して記録。敵種・敵Lv・ドロップ・基礎EXP/Goldの正本を変更せず、必要な修正は資料と同時に管理。
- [EVENTS.md](../EVENTS.md)に記載されたイベントID・発生条件・選択肢を用いて、最低限の選択イベントを実装。後から増やしやすいデータ構造にする。パーティ加入イベントは工程2の仕様に整合させる。
- **黄金像**：探索に潜るたび1回祈ることができ、到達階層で装備／アイテム／動物・魔物の候補が変わる。**人間の加入はガチャから出さない**。工程2の初回犬加入（導入イベント）とは別のフラグを使う。
- **祈り→入場→即帰還の周回**は設計上起こり得るため、仕様の「潜るたび1回」を勝手に取り消さず、シミュレーション上の効率を記録し、是正が必要なら提案に留める。
- 1F・11F・21F…の到達解放ルールを保持。10F突破で11F開始地点が解放されるが、11Fの敵・イベントを作る義務はない。
- 獲得理由・出現割合・報酬の履歴を、ログとテストで確認できるようにする。

## 受入条件

- [ ] 階層ごとの遭遇種率／敵種率／宝箱抽選率が100%に整合し、**大量試行の実測比率**が設定に近い。
- [ ] 敵LvとEXP・Gold・ドロップ率が文書の正本から矛盾なく取得でき、ボス固定・未到達の開始地点ロックが正常。
- [ ] イベントの選択と結果・フラグがセーブ後も再現し、加入イベントが重複しない。
- [ ] 黄金像の1探索1回・到達深度別候補・非人間排出がテストされる。
- [ ] 実際のWindows試遊版／イベント画面／ドロップログ／ヘッドレス結果・PR／CI証拠がある。

**対象外**：町の大規模建設、20F以降の大量データ、正式ストーリーの大量追加。
