# 工程2 — 人間＋配下のパーティ編成と死亡

[工程案内](README.md) ｜ [工程1](PHASE_01.md) ｜ [仲間台帳](../ALLIES.md) ｜ [全体仕様](../../SPEC.md)

## 目標

工程1のソロ戦闘と町・セーブを壊さず、**最大6体のパーティ**に拡張する。**人間は主人公＋人間仲間2名、動物・魔物は各人間につく配下1体ずつ**。人間と配下の区別・個体管理・死亡・加入を体験できることが完了条件。

## Codex実装内容

- 種族ID／個体ID／人間の指揮者IDを分離。編成・控え・個体ごとのLv／EXP／HP・SP・装備可否・スキル名を保持。**最大人間3／最大配下3／1人間につき配下1体**をUIとデータの両方で保証。
- 主人公も配下を持てる。人間の指揮者がいない配下は単独で出撃できない基本ルールを**仮設定**。付け替え方法、指揮者死亡時の扱いは正式未決なので仮設定を記録し、処理を拡張可能にする。
- **初回死亡の後、黄金像が怪しく光り、犬が加入するイベント**を今回実装。ユーザー指定の「将来導入」を**この工程で初めて取り込む**。初回探索が主人公1人であることを変えない。黄金像の繰返しガチャは工程4まで作らない。
- 人間仲間2名を**ゲーム開始時には与えない**。実際の加入導線はイベントなどで少なくとも1名を実装し、残りはテスト専用の編成データでも検証できるようにする。加入タイミングの創作判断が必要なら、無理に正式シナリオを決めず仮案として扱う。
- SPD順の自動戦闘で、主人公／人間／配下が適切に行動できる。配下の手番を独立とするか指揮者への追随型にするかは未確定。**まず仮の標準方式を1つ実装し、スイッチまたはテストで比較可能にする**。既存の単独戦闘も維持。
- 敵が1体だけだと6体編成が容易になりすぎるため、**敵グループ・複数の敵**も試作用に追加し、単独探索と比較する。固有効果の数値はSKILLS、敵の行動パターンはENEMIESに置く。
- **仲間HP0は即死亡・原則永久離脱**。例外的に戻ってくるキャラは能力として管理。主人公は別扱い（死亡後町へ戻る）。死亡や出撃中の状態はセーブ・ロードで整合を保つ。
- **友好度・忠実度は将来のため保存フィールドを用意するだけ**。本工程で戦闘補正・連携や恋愛演出を作らない。

## 受入条件

- [ ] 最大6体を超えて出撃できない。人間の枠や配下の紐づけが不正な状態なら安全に修復または拒否。
- [ ] 初回は単独、初回死亡後に犬を**1度だけ**獲得（リロードや再死亡で重複しない）。
- [ ] 人間加入・動物加入・控えへ移動・配下付け替え・死亡がセーブ後も一貫。
- [ ] 複数敵／複数味方でも速度順・対象選択・死亡判定が破綻せず、ソロ10Fループが壊れない。
- [ ] 1体／3体／6体の検証編成についてヘッドレス勝率・死亡率・平均ラウンドを比較。
- [ ] 編成UIの実画面、Windows試遊版、CI・自己レビュー・証拠を残す。

**対象外**：本格的な友好度連携・忠実度による戦闘AI、隊列（まだ候補）、町の全面改修、黄金像ガチャ全体、20F以降。
