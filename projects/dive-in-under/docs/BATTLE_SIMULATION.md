# ヘッドレス戦闘シミュレーター — 開発要件（導入決定・未実装）

[全体仕様](../SPEC.md) ｜ [戦闘共通仕様](COMBAT.md) ｜ [階層抽選](FLOORS.md) ｜ [敵](ENEMIES.md) ｜ [スキル](SKILLS.md) ｜ [実装進捗](IMPLEMENTATION_STATUS.md)

> **採用決定**：2026-10-17、ゲーム本体と同じ戦闘処理を用いて、大量の戦闘を画面なしで再現する環境を**Codex実装時に作る**。今は設計準備のみで、ゲームコードや新しいシミュレーターはまだ作らない。

## 目的と構造

- **戦闘ロジックは1つ**。ゲーム画面もヘッドレスランナーも同じ戦闘エンジンを呼び出す。ダメージ計算・AI・状態異常をシミュレーターに再実装しない。
- ランナーはUI・描画・音声なしで実行可能とする。最初は単独の戦闘検証、次に1〜10Fの連続探索検証、仲間・配下実装後は6体編成を検証。
- **同じゲーム・シナリオ・データ版・乱数シードは同じ結果を返す**（乱数の注入、並び順、スキル判定の再現性を確保）。
- **修正前／修正後を同じ条件・同じシード集合で比較**し、勝率・死亡率・平均ターン数・残HPなどの差と試行数を出す。比較対象のゲームコミット・設定版・データ版もレポートに記録する。
- Codexは必要に応じシミュレーションの実行と結果比較を行い、**数値変更の根拠**を短く報告する。プレイヤーの体感の最終判断は試遊で行う。

## 入力（実装時の最低要件）

- シナリオ：敵種ID・敵Lv・敵グループ、主人公／味方のLv・装備・スキル・所持SP・HP、必要ならフロアの出現率と宝抽選設定。
- 試行回数（例：最初は1,000、まとまったバランス比較では10,000）・乱数シード・実行対象のビルド／データの版。
- 比較対象は同一シナリオに固定し、複数シードで試す。敵のスキルや戦況で乱数呼出し回数が変わる場合もあり、**同一シードで「必ず同じ乱数列が各行動に当たる」とは限らない**。可能なら戦闘・ドロップ・イベントの乱数ストリームを分離する。
- **探索の撤退判断も入力として定義**（例：あえて最後まで潜る／HPが一定割合以下なら戻る／イベント時に戻る）。これを指定せずに「10F到達率」を比較しない。

## 集計指標

| 対象 | 最低限の出力 |
| --- | --- |
| **単発戦闘** | 試行数、勝率、平均・中央値ターン数、勝利時の残HP（平均・分布）、主人公死亡率、仲間死亡率 |
| **継戦** | SP消費量、HP減少、装備耐久損耗、状態異常発生数、行動不能回数、戦闘打切り率 |
| **階層探索** | 階層別到達率・死亡率・帰還率、10Fボス到達率／突破率、EXP・Gold・戦利品の平均量 |
| **変更比較** | 変更前後の各指標、差分、実行条件、シード集合、ゲームコミット、数値データの版 |
| **安定性** | 進行停止・無限行動・異常なダメージ・負のHP等の検出数と再現用シード |

- 平均のみでなく**中央値・分位点（例：下位10%／上位10%）**を出し、極端な事故死が隠れないようにする。可能なら勝率・死亡率に**信頼区間**を併記。
- 例：敵ATKを変更した際に「勝率だけ上昇、平均ターン数は変わらず、味方残HPだけ低下」等の差を比較できるようにする。
- 出力は読みやすいテキスト要約と、後続比較できるJSON／CSV等の機械可読形式（具体的なCLI仕様は実装時に確定）。

## 工程1の追加検証：状態異常4効果

[工程1](dot/PHASE_01.md)にて、**毒・暗闇・麻痺・防御態勢**を本体と同一ロジックで検証する。固定シードで付与成功／失敗・解除・複数状態・同種再付与・SP不足・途中セーブ／再開・HP0を確認。

- 毒の継続HP減少と死亡、暗闇中の命中率低下、麻痺中の行動スキップ、防御態勢中のDEF補正を確認する。
- **状態あり／なし**の勝率・死亡率・残HP・平均ラウンド・10Fボス突破を比較し、**初回も通常探索として統計へ含める**。
- エフェクトはゲーム画面でのみ描画。**共通戦闘イベントログ**と戦闘計算の乱数は演出に影響されない。

## 必須検証シナリオ

1. 初期装備の**主人公1人 vs 1Fの通常敵**。装備あり／なしを比較。
2. 同じ敵IDについて、階層台帳の**敵Lv範囲**が勝率・EXP・Goldをどの程度変えるか。
3. **1〜10F連続探索**：HP／SP／装備耐久の持越し、固定10Fボス、退く判断を含める。
4. 主人公・仲間のLv差、装備の組合せ、回復スキルと状態異常の有無を比較。
5. 最大6体の編成、友好度・忠実度・連携は**そのシステムを実装した後に追加検証**。

**初回も検証対象**：新規開始直後の探索は通常ルール。初回帰還・初回HP0敗北・初回の10F突破を固定シードで検証する。**強制死亡シナリオと、その統計上の例外扱いは廃止**。

## 実装時の受入条件

- [ ] 本体とヘッドレスランナーが**同一の戦闘コア**を利用し、別々の計算式を持たない。
- [ ] 同じシード・同じデータ・同じ環境で実行した結果を再現できる。
- [ ] 試行回数を指定し、単発戦闘の**勝率／死亡率／平均ターン数／残HP**を取得できる。
- [ ] 修正前後で同じシナリオ・シード集合の**比較レポート**を作れる。
- [ ] 10F拡張時に連続探索の生存率・到達率・報酬も取得できる。
- [ ] 性能を優先して画面なしで実行でき、単純な回帰テストを自動化できる。
- [ ] 各指標の試行条件を記録し、テスト結果を「適切な難易度の証明」と過大評価しない。

**制作順序**：最初のCodexによる共通戦闘処理の実装と同時に**最小限の単発戦闘ヘッドレスランナー**を追加。その後、10Fまでの階層システムができたら連続探索モードを追加。シミュレーター独立の専用GUIは当面不要。

**注意**：「ちょうどよい勝率」はゲームが求める体験によって変わる。まず実際に試遊してターゲット（序盤・中盤・ボス、初期装備・強化装備など）を決め、そのターゲットに対して自動検証する。
