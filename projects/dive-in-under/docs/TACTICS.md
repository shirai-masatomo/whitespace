# 作戦・行動設定・隊列対象・行動順 — 採用仕様

更新日：2026-10-20（日本時間）。状態：**仕様採用・実装／実機確認は別途**。

本書は同日のユーザーとの仕様協議を記録する正本。0.9.0の試作実装、旧「完全自動」「SPD降順のみ」「隊列は未採用候補」の記述より、本書の採用事項を優先する。ただし本書の作成は、コード変更・配布・仲間加入工程の完了を意味しない。

## 1. 目的と範囲

10Fまでの体験の品質を高め、後続階層へ拡張できる戦闘基盤にする。戦闘前の設定だけでなく、自動戦闘中の作戦切り替えでも戦略性を持たせる。11F以降の追加を本書の前提にしない。

主人公単独でも設定と自動行動が成立すること。部隊保存・複数キャラの行動順は複数人編成を扱える設計とするが、人間・配下の加入方法や実装工程をここで変更しない。現行1対1の実装制限と、採用された部隊仕様を混同しない。

## 2. 用語

- **キャラ個別の設定**：各キャラのスキル使用ルールと優先順。本書では便宜上「行動設定」と呼ぶ。
- **部隊の保存セット**：各キャラの設定の組み合わせを保存したアセット。本書では「作戦」と呼ぶ。
- 上記の画面上の正式名称は整理案。ユーザーは仕組みを採用し、部隊セットを「作戦」と呼ぶ案を提示しているが、個別名称まで正式確定した扱いにはしない。
- スキル使用ルールの優先順と、キャラ同士の行動順は別の設定である。

## 3. 採用事項：キャラ個別の行動設定

- 各キャラについて、**スキル・条件・対象**を組み合わせた行を設定できる。
- 行の優先順をユーザーが調整できる。単にランダムなスキルを使わせるだけの方式にしない。
- スキル自体の効果・SP・クールダウン等の正本は[SKILLS.md](SKILLS.md)。個別作戦に技能効果を重複定義しない。
- 条件一覧、数値閾値の指定方法、1行の条件数、行数上限、複数条件のAND／OR、同条件時の対象選択は未決。先に出た「条件2つまで」は提案であり確定上限ではない。
- 「上から最初の実行可能な行を使う」「全行不成立なら通常攻撃」「未装備スキルの設定を保持して再装備で復帰」は整理・実装案。採用済みの対象不在スキップ（第5節）以外の詳細は未決事項として詰める。

## 4. 採用事項：部隊セットの保存・選択・戦闘中変更

- 部隊ごとに、各キャラの行動設定の組み合わせをアセットとして保存できる。
- 複数のセットに名前を付け、お気に入り登録できる。
- 1つを選択しておき、戦闘中は選択中のセットに従って各キャラが自動行動する。
- **戦闘中も別のセットへ変更できる**。完全自動とは「指揮変更不可」を意味しない。
- 例：「全員防御寄り」から「全員攻撃寄り」へ切り替える。
- 例：「主人公は攻撃寄り、配下は防御寄り」のセットへ切り替える。
- 「全員防御寄り」などはセットの構成例であり、全員に未所持の防御スキルを付与する仕様ではない。
- 味方行動順も作戦に含めて保存することは提案中。ユーザーによる行動順制御そのものは第6節のとおり採用済み。
- 保存先・永続化の範囲、保存数／お気に入り数、複製・上書き、キャラ入れ替え時の対応、戦闘中の個別編集可否は未決。現行「起動ごと新規開始」の扱いを勝手に変更せず、作戦プリセットの保存と冒険のセーブを区別して設計確認する。

## 5. 採用事項：敵の前衛・後衛とスキル射程

- **敵にも前衛・後衛の概念がある**。
- 行動設定の対象として敵の前衛・後衛を指定できる。
- **対象指定と攻撃可能範囲（スキル射程）を分離する**。対象設定によってスキルの射程制限を無視しない。
- **射程内に指定対象がいない場合、その行を飛ばし、次の優先設定を判定する**。
- 例：後衛を攻撃できるスキルで後衛を狙う行を上に置き、それが使えない場合に前衛を攻撃する行へ進む。
- 前衛専用のスキルが存在する場合、対象欄で後衛を選んでも後衛へ届かない。これは分離ルールの説明であり、「全近接攻撃は後衛不可」を一括で確定したものではない。
- 各スキルの具体射程、前衛不在時の後衛の扱い、隊列変更、列ごとの人数上限・補正、味方への回復射程は未決。既存の能力計算に隊列倍率を勝手に追加しない。

## 6. 採用事項：味方行動順を指定し、速い味方を待たせる

ユーザーが味方の行動順を制御できる。指定順を守るために速い味方を待たせる方式であり、遅いキャラの素早さを引き上げたり、敵を飛び越えて割り込ませたりする方式ではない。

### ユーザー指定の基準例

| 陣営 | キャラ | 素早さ |
| --- | --- | ---: |
| 味方 | A | 10 |
| 味方 | B | 20 |
| 味方 | C | 30 |
| 敵 | O | 5 |
| 敵 | P | 15 |
| 敵 | Q | 25 |

味方の指定順：**B → A → C**

全体の行動順：**Q → B → P → A → C → O**

- Cは素早さ30でも、BとAが先に行動するまで待つ。
- 最初の味方候補B（20）より速いQ（25）が先に動く。
- Bの後はA（10）が味方候補なので、P（15）が先に動く。
- Aの後、C（30）が行動可能となり、O（5）より先に動く。

### 基準例から導く判定手順

1. そのラウンドの未行動の味方について、指定順の先頭だけを行動候補にする。
2. その味方と未行動の敵を素早さで比較し、次に行動するキャラを決める。
3. 味方が行動したら、指定順の次の味方を候補にする。敵が行動した場合、味方の先頭候補は変えない。
4. 行動済みキャラを候補から除き、繰り返す。

これは上記の通常ケースを再現する仕様整理であり、下記の未決例外を暗黙に確定するものではない。

既存[COMBAT.md](COMBAT.md)では1ラウンド各1行動、SPDは行動回数を増やさず、同速は固定seed乱数としている。今回の順序指定で追加行動が生じる仕様は採用していない。同速処理を新しい候補方式でもそのまま使うか、待機・行動不能をどう数えるかは確認する。

## 7. 未決事項・先に出た提案の扱い

以下は勝手に本実装の確定仕様にせず、資料に決定を追記してから確定する。

- 戦闘中の作戦変更を、実行中行動の終了後／次の行動／次ラウンドのどこで反映するか。
- 作戦切り替えのコスト・回数制限。先に出た「ターン・SP消費なし」は提案。
- ラウンド途中に行動順を変更した際、未行動キャラへどう適用するか。行動済みキャラの再行動は許可された仕様ではない。
- 同速候補の扱い、SPDの戦闘中増減を評価するタイミング。
- 先頭キャラの死亡・離脱・麻痺・睡眠等の行動不能、復活・途中加入時の扱い。毒の処理や残りターン減少のタイミングも合わせて定義する。
- 味方の順序指定を省略する場合の既定順、敵側にも順序制御を導入するか。
- 複数対象候補の絞り込み、条件全不成立・SP不足・クールダウン時の処理、実行理由・不実行理由の表示。
- 戦闘中のセット切り替えUIとショートカット。既存Space停止／再開は保持するが、「停止中の作戦選択UI」は設計案。
- 石像等の予告・強打を確定パターンにするか。切り替え操作が可能でも、予告に気づく時間と防御が間に合う行動順・効果持続が必要。今回の採用だけで既存のボス試作値を正式採用した扱いにしない。
