# AUTONOMY — DIVE DIVE

**完全自律型**。共通方針は [WhiteSpace 自律運用](../../docs/AUTONOMY.md)。このファイルはDIVE DIVE固有の判断境界。

**現在は高速試作フェーズ。定期自動再開はPAUSED**。以下の過去の常設許可や継続規則より、最新の停止・指定範囲と本書の軽量サイクルを優先する。

## 常設の再開許可（2026-09-20）

ユーザーがDIVE DIVE / WhiteSpaceの自律開発について、**30分ごとの自動再開**と開発・テスト・headless検証・必要最小限のGPU確認・自己レビュー・AI指摘の反映・改善・文書/タスク更新・参照監査後の不要資産整理・commit・通常push・CI確認を継続して許可した。同じ範囲の再承認は不要。Codexアプリのこのタスクに常設設定 `dive-dive`（DIVE DIVE 自律改善を継続）を作成済み。共通の1時間監視に対する本PJの例外とする。

CHANGES / SELF_CONTINUEなら次タスクへ進む。実行中の同じ作業を重複起動せず、他セッションの未commit変更を上書きしない。通常はheadless/background、GPUは画面外・非捕捉・無音。フォーカス・マウスを奪わず、終了できるのは所有を確認した自分の検証プロセスだけ。

常設許可の対象外: force push、Git履歴の書換え、重要データの不可逆な大規模削除、有料サービス/課金、外部サービス/Steamへの実公開、契約/規約への同意、権利/ライセンス上の重大判断、秘密情報/認証情報の変更や外部送信、人間が起動したアプリ/ゲームの強制終了。必要な場合だけ具体的な判断を求める。ユーザーの停止・範囲変更指示を優先する。

## レビュー受け渡しの正本

人間方針と外部AIレビューの正本は **origin/main** の以下2ファイルとする。

- `projects/001-first-release/HUMAN_DIRECTION.md`
- `projects/001-first-release/EXTERNAL_AI_REVIEW.md`

各セッション開始時に `git fetch origin main` を行い、作業ブランチ内のコピーだけを信用せず、
`git show origin/main:projects/001-first-release/HUMAN_DIRECTION.md`
`git show origin/main:projects/001-first-release/EXTERNAL_AI_REVIEW.md`
で最新内容を読む。

main側の方針/レビューが作業ブランチより新しい場合は、**実装開始前にTASKSへ具体的なP0/P1作業として落とす**。
「読んだ」だけで未タスク化のまま進めない。

PROJECT_STATEには、最後に取り込んだmain側のHUMAN_DIRECTION/EXTERNAL_AI_REVIEWのcommit SHAを記録する。
これにより外部レビューが未反映かを機械的に確認できる。

## 試作サイクルと検証選択（2026-09-21）

今は面白い場所を速く発見する段階。通常は **実装 → 最低限の起動 → 変更箇所の操作 → 代表画面1〜3枚 → 自己批評 → 次案**。毎回の全check/全経路/全衝突/両renderer/全画像/export/benchmarkは不要。既存のテスト網を増やすことより、形と配置を大胆に試し、見る・捨てる・作り直す時間を優先する。

| 変更・節目 | 必要な検証 |
| --- | --- |
| 文書のみ | 差分・リンク・方針の矛盾。ゲーム起動/buildは不要 |
| 局所の小物配置・材質・地形微調整 | 軽い起動と対象箇所の実操作、代表1〜3枚。触れる形を変えた時はその接触だけ。通常はForward+のみ |
| 大きな地形・移動/physics・collision・酸素/救助 | 関連案をまとめた節目にcheckと影響経路/実衝突を検証。明らかな操作不能やすり抜けは先に直す |
| 人間レビュー候補・merge前・Release候補 | 全check、必要な全経路/実衝突/GPU、Windows export。renderer共通描画変更や配布互換性の節目は両renderer |
| 描画負荷に疑い・大規模密度変更 | 対象視点のbenchmark。小変更ごとの全視点測定はしない |

既存 `dev.ps1 check` は節目用として維持する。通常は直接対象テストや該当区域の入力を選び、全体の `visual` / `evaluate` を義務にしない。画面は入水・変更場所・探索のうち関連する1〜3枚で十分。詳細な連続画像やREVIEW_PACKETは節目だけ。

数回の試作を1制作サイクルにまとめ、必要な検証 → TASKSの状態/STATEの重要変化 → commit/push → CI確認。小変更ごとにcommit/文書/CI待ちを挟まない。CI実行中は可逆な次の試作を進めてよいが、失敗は制作より先に修正し、merge/レビュー提出前には対象SHAの成功を確認する。

GPUは画面外・起動時no_focus・マウス非捕捉・無音。ユーザーのゲーム/エディタは終了しない。終了してよいのは自分が開始し所有を確認した検証プロセスだけ。

## 自律的に判断する

小規模機能、UI、数値、足場サイズ/配置、酸素、移動、カメラ、仮素材/演出、テスト、CI、環境改善、バグ修正、リファクタリング、タスク分割。可逆な判断は人間を待たない。
仕様は可変。既存コードより現在のコンセプトへの適合を優先する。中核は下方向へ進む3D水中アクション、自然沈降・足場・酸素・広い海・連続した失敗/深度損失。海上開始、Space浮上、E急降下の追加酸素消費、接触で瞬時補給を現在の方向性とする。
光/水/Fog/スケールから順に品質を上げ、プリミティブを完成扱いしない。Godotの具体的制約が判明した場合だけUE5移行を判断事項として提示する。

## レビュー

各試作の前に「この画面で何を迷わせたいか」を一文で定義し、候補ごとの手掛かり/見返り/代償を記録する。代表1〜3画面の同条件比較→実操作→批評を行う。選択が読めることと経路が通れることを混同しない。3択やオブジェクト数を機械的な合格条件にしない。通常は画面確認と短い批評に留め、採用比較は節目に既存REVIEW_PACKETへまとめる。

- HUMAN_DIRECTION.md は最新の人間方針として毎回必読。未反映項目があれば最優先でTASKSへ落とす。
- EXTERNAL_AI_REVIEW.md は外部AIレビューとして毎回必読。CHANGESは人間に聞かず解消する。
- 節目だけAI_REVIEW.md / REVIEW_PACKET.mdを短く更新する。遊び方、変更3〜5件、テスト、画像、重要な懸念、SELF_CONTINUE / AI_REVIEW / HUMAN_REVIEW。
- AI_REVIEW.mdはPASSなら継続、CHANGESなら人間に聞かず修正し再評価、HUMAN_REVIEWなら具体的な判断点を人間へ渡す。
- レビュー対象commit/作業差分とレビュー者を明示。同一Codexによる自己レビューを独立レビューと呼ばない。古い指摘は現行コードで再現するか確認。
- 人間レビューは中核ゲームループ → Vertical Slice → ほぼ完成版 → RCを基本とする。実装終了そのものは停止理由にしない。

## 人間が必要

核の変更、成立する複数案の好み、AIで判定困難なプレイ感、大きな創作判断、上記節目、有料サービス、権利リスク、契約・販売・実公開。秘密情報/外部アカウント/不可逆な大規模削除も共通方針に従う。

速度・到達性・酸素余裕・回復・深度損失・復帰時間・カメラ内認識・候補経路・判断間隔を可能な限り先に測る。「面白さ」はテスト合格から推測しない。

## 記録

STATEは現在地、TASKSは次の作業、HUMAN_DIRECTIONは人間の最新方針、EXTERNAL_AI_REVIEWは外部AI指摘、REVIEW_PACKETは評価入口、AI_REVIEWはCodex自己判定/対応。重要な環境問題はSTATEの再実行メモ、詳細ログはartifacts、過去はGit履歴。人間向け報告は現状2〜4行、変更最大5件、次最大3件、必要時だけ人間判断。

## リアル層の制作中の例外（2026-09-19）
