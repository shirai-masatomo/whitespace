# ホイッスル牧場（仮）

**空き地に牧場を築き、柴犬といっしょに牧場主を守る。** 育成 × 経営 × 間接防衛の小さなWindowsゲーム。

[Play.cmd](Play.cmd) をダブルクリック、または `build/WhistleRanch.exe` を起動。ブラウザ・Godot Editor不要。Stage 1 → 評価・購入 → Stage 2を遊べる。フォルダ名 `sporehollow` は既存リンク維持用。DIVE DIVEとはコード・TASKS・ビルド・CIを分離している。

## 遊び方

1. 空き地をクリックして**牧場主の初期位置**を決める。最初の仲間は柴犬Lv1が1匹。犬は牧場主のそばから開始。
2. 「時計を開始」。Stage 1では**18秒後に最初の襲来**。資材で壁・門を配置する。侵入中も建築・撤去できる。
3. 侵入者は牧場主を狙う。犬が気づけば自律追跡・吠えて追い返す。疲れたら餌、遠くの敵には指示、経路を変えたいときは門。
4. **拘束されてもまだ負けではない。** 入口へ運ばれる途中に犬が相手を追い返すと救出。その場所から防衛を続ける。牧場外へ連れ去られると敗北。
5. 全襲来を撃退すると評価・EXP・Gold。購入後、所有動物・Lv・Gold・所持品・卵・購入強化を持ってStage 2へ。鶏を買うと産卵・回収・売却/餌への交換もできる。

| 操作 | 効果 |
| --- | --- |
| 1 / 壁 → 地点クリック | 資材3、HP8。犬も敵も通常通れない。敵は破壊可能 |
| 2 / 門 → 地点クリック | 資材5、HP6。閉じた状態で設置 |
| 3 / 門を開閉 → 門クリック | 開けば犬も敵も通る。閉じると両方を遮り、敵は破壊可能。占有中は操作不可 |
| 4 / 餌 → 地点クリック | 餌1・指示力3。疲れた犬が寄り道して元気48回復 |
| 5 / 撤去 → 壁/門クリック | 耐久に応じ、建設費の半分以下の資材を回収 |
| 6 / 卵を回収 → 巣クリック | 地面の卵を所持品へ。鶏を所有したStageのみ巣が現れる |
| Q / 笛 → 地点クリック | その場所を守る。近い敵への自律反応を優先 |
| W / 待機 → 地点クリック | その場所へ移動して待機。隣の敵には吠えるが追跡しない |
| E / 徘徊 → 地点クリック | 周辺を歩いて見張る |
| R / 敵を指定 → 侵入者クリック | 指定した敵を遠くまで追跡。連れ去り役の救出にも使える |
| A / おまかせ | 自律判断へ戻す |
| Space / 停止・再開 | **停止中は動物指示だけ**。建築・撤去・餌・門開閉・卵回収は不可 |
| 速度 ×1 / ×2 | 時間の進行を切替。停止中に選んだ速度は再開後に適用 |
| この日の最初から | 当日開始時へ戻る。購入資産・開始時の所持品を復元 |

指示は戦闘を代行しない。忠誠度に応じて反応まで少し時間がかかり、一定時間後におまかせへ戻る。指示力は現在、餌の設置に使用（最大10、約3.6秒で1回復）。犬への指示は無料で、連打すると反応待ちをやり直す。壁で犬自身を閉じ込めないこと。

## ゲームデザイン正本

### 今回確定した核

**空き地 → 主人公配置 → 時計開始 → リアルタイム建築 → 襲来 → 壁・門・柴犬で阻止 → 連れ去り or 防衛成功。**

- 四角い空き地と入口を基本盤面にする。固定中央柵・固定門を前提にしない。
- 主人公は侵入者の重要標的。拘束と連れ去りを分け、移送中の救出を可能にする。今回、侵攻中の主人公は自分では移動しない。
- 壁・門は資材制、HPを持ち、動物の経路も変える。敵は通常移動・門破壊・壁破壊の所要行動数を比較。迷路を塞いだだけでは勝てない。
- **停止＝判断、進行＝実行。** 停止中は動物の命令意図だけ変更する。位置・資材・餌・施設・畜産物・時間は変化させない。
- 忠誠度は反応時間と指示維持時間に使う。攻撃力・元気消費・追跡速度を上げる値にはしない。
- 動物はカテゴリー/種類/個体Lv/EXPを持つ。柴犬は警戒・追跡・疲労・休憩・摂食、鶏は怖がる・逃げる・産む。プレイヤーの直接攻撃はない。
- 主敗北は主人公の牧場外への連れ去り。個別施設の破壊は損失として継続する。動物死亡・畜産物盗難も将来実装時は即敗北としない。
- 牧場全体HPゼロは**敗北条件候補**。HPの対象・損害算定と合わせて後で試す。現時点の実装済み条件ではない。
- 敵Controllerとルールは描画から分離。最初は主人公を狙う誘拐型だけ。破壊型・動物攻撃型・バランサー・支援型・妨害型は拡張候補。

| 次Stage | 新しい空き地・資材枠で開始。所有動物/育成/経済/購入強化は引継ぎ。今回建てた壁/門の配置と未使用建築資材は当日限り。施設配置そのものの持越しは今後検討 |

**襲来設定:** [game/stages.gd](game/stages.gd) の `STAGES` が正本。`first_attack_seconds`＝初襲来、`waves`の件数＝Wave数、各 `start_seconds`＝初襲来からの開始オフセット、`count`＝人数、`interval_seconds`＋`jitter_seconds`＝間隔とランダム幅、`role`＝敵種類、`entries`＝入口候補。`repeat_waves` と `repeat_interval_seconds` で継続襲来を設定できる。継続時は `time_limit_seconds` まで守れば成功。通常2Stageは全敵の退散で成功する。

### 自己評価・未確定

最初の試作では放置でも全勝したため、襲来の重なりと疲労回復を修正した。現在の同条件32試行では、放置/建築のみは両Stageとも0/4、指示＋餌/建築併用は4/4。建築で拘束回数も変わる。ただし、固定方策の比較であり人間の勝率や面白さの証明ではない。

**次に確かめる核:** 建築で救出までの時間を稼ぐか、開門して犬を先回りさせるか、餌を置いて追跡から離すか。現状は指示と餌だけでも勝てるため、建築が毎回必要か・毎回同じ囲いが正解かは未確定。動物や店の商品を増やす前に、配置と侵入中の判断を試す。

正式設定、侵攻中の主人公移動、牧場HP、追加の敵役割、施設持越し、動物損失は未確定/未実装。オンライン・Steam・セーブ・Stage 3以降は今回作らない。大きな核の変更と好みは人間が判断する。

## 開発・検証

Godot 4.7.2 / GDScript / Compatibility。通常はheadless。プロジェクトフォルダから:

```powershell
./tools/setup.ps1       # 公式GodotとtemplatesをSHA512検証して取得
./dev.ps1 test          # 建築・経路・誘拐/救出・pause・育成の回帰テスト
./dev.ps1 evaluate      # 2Stage × 4方策 × 4 seeds、観察JSON
./dev.ps1 check         # import → test → evaluate → Windows export → exe起動
./dev.ps1 visual        # 画面外・非捕捉・無音の実GPUとGodot入力試走
./dev.ps1 editor        # Godot Editor
```

- `game/world.gd`: 固定tick（0.25秒）、コマンド検証、建築、動物、拘束/救出、評価/育成/経済。
- `game/stages.gd`: ステージ別襲来設定。`game/raider_ai.gd`: 敵の目標Controller。
- `game/main.gd`: 日本語UI・描画・入力。停止制約はモデルにもありUIを迂回しても建築不可。
- `artifacts/evaluation.json`: 方策比較。`artifacts/campaign.json` / `visual-play.json`: 操作履歴・個体経路・建設/損壊・捕獲/救出・資材・経済・評価・設定・seed・時刻。
- 画面の「観察JSON」は `%APPDATA%/Godot/app_userdata/ホイッスル牧場/observations/latest.json` に保存。ゲームのセーブではない。
- CIはWindowsでツール準備→check→ビルド/観察記録を保存。通常試作は関連テストだけ、制作サイクルの節目にまとめて検証。面白さはテスト成功と別に評価する。
