# 実装担当への接続メモ

この依頼は素材制作として扱い、ゲームコード・本番シーン・UID・資源量・当たり・速度を変更していない。以下は接続契約と検討事項であり、新しいルールの採用/実装完了を意味しない。

## 今回の素材を使う接続

1. 既存の連続地面色 → rock_ground → 境界 → 疎な散布物 → 任意の影 → 接地点で並べた岩/木 → 状態差分 → 局所FX → UI。
2. 既存の岩/木の位置・作業進行を参照し、manifestの静止状態を選ぶ。新しい状態名を保存形式へ追加することは素材取り込みの必須条件ではない。
3. 既存作業の打撃イベントへ石粉・木屑を接続。実際のヒットイベントがない場合は実装側で検討し、描画フレームからダメージやドロップを発生させない。
4. 完了の確定処理に合わせ、岩本体→露出面/瓦礫、木→切株/丸太を表示切替。元の確定処理以外から資源を追加しない。消去時刻も既存状態に従う。
5. 採掘後は4近傍の岩壁maskを更新。内角を使う場合だけ斜めも確認。地表境界は隣接岩の有無だけでなく既存バイオームの視覚情報に基づいて選ぶ。
6. 影を一度だけ描く。FXは既存manifestの時間で非ループ、終了後消去。大きなフラッシュは不要。

## プレイ上の識別

- decor/mineable、decor/cuttableの区別は既存資源データ・作業可否を正とする。見た目から新たな物理IDを推測しない。
- 装飾は小石/薄い草・岩肌を使う。rock_nodeは採れる岩へ割り当てる。
- ホバー/選択は画像alphaの輪郭から動的ハイライトを作成可能。状態差分にも追従させ、文字・選択範囲はUIとして別描画する。
- 48×54というキャンバスだけで全岩を同じ物理サイズに変更しない。manifestのowner占有1セルは既存対象に対応する。

## 別途判断するシステム提案

依頼に含まれるクラスター生成、採掘/伐採の優先カテゴリ、作業工程の追加、SEフック、再生/枯渇、地形移動速度差はゲーム側の設計事項。今回は素材の条件として強制せず、既存ルールとの差分を実装担当が整理する。特に再生成・数量・速度は画像から決めない。

## 受入確認

- 同一岩が足元を移さず4段階で削れ、最後に1セルだけ消える。
- 連結岩壁の隣接再評価で端面が更新され、地面が消えない。
- 草原/岩盤/砂利の境界に四角い枠や二重線が出ない。
- 石材アイテムと瓦礫、木材アイテムと丸太の演出を二重ドロップとして数えない。
- 人物・動物・仕事札・落とし物と重ね、実際のズームで対象可否が読める。
- 背景色・影・停止/時間倍率・作業完了後の消去を隔離描画で検証する。
