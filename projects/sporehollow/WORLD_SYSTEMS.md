### 現在の確定仕様と仮設定（2026-10-10）

動物/お金/アイテムを像の選択操作から予約し、2夜目から夜のみ、現地3秒、1晩1回、完了時カルマ+3、翌朝受取。動物は鶏/猫/ドーベルマン/ウシガエル/ハリネズミ、アイテムは首輪/きのみ、お金は40/60/90G。既存ProgressDataの抽選をそのまま使い、柴犬は除外。受入不可の動物は購入と同じ受入待ちとして個体を保持する。

祈り成立時にcategory、seed、成立時karma、PrayerID、受取日を保持し、翌朝にRewardRecordを一度生成・保存して決済。取消・被弾・PAUSE・朝の復元は既存Job/チェックポイントへ統合。確定指定のカルマ+3/回、D+1取引のニュース、D+2噂、D+3治安変化・追加襲撃上限2体を流用。動物/アイテムで未実装の感染等を報じず、当面は街道の取引・盗難へつなぐ。調整済みの最終設計ではない。

日開始の永続保存・復元を実装済み。日中の取引直後や任意tick保存は未対応。独立朝フェーズはなく、旧morning/shop記録は昼開始へ変換する。アイテムの高Rarity化、カルマ減衰やカテゴリ固有勢力は後続。

## 0. 指定と補足の区別

### ユーザーの採用指定

- 父から受け継いだ牧場、中央の巨大な黄金像、父の消息と像の謎。
- 最初の敵は像を知らないならず者。祈りが初回襲撃の原因ではない。
- 祈りは本当に願いを叶えるが、外の世界に反作用を蓄積する。
- カルマ・情勢の内部値は通常画面に表示せず、ニュース・来訪・敵・景観で感じさせる。
- 外周柵を森（仮）に変更。内側の森は開拓可能、外側は非プレイ領域。
- 襲撃は複数方向から。将来の入口を常に公開する固定門方式をやめる。
- 敗北は主人公の連れ去り、または像の破壊／持ち出し。途中救出が可能。
- 家畜、通常施設、主人公、像で守るものと敵の目的を分ける。

## 1. 地形の3区分と敗北境界

同じ座標モデルで次を明示する。

1. 開けた牧場：現在の生活・建築場所。
2. 開拓可能な森：行動範囲内にある地形。木を取り除くと使える土地になる。
3. 森の奥：行動範囲外。建築・伐採・手動移動・動物誘導の指定不可。敵の登場と搬出の世界側。

**開けた土地の端≠敗北線。** 木を切っても外側の固定境界は動かない。森の中や樹冠の下へ運ばれただけで敗北にしない。木をなくしたら脱出口が消える処理にもならない。

初期の中央空間・主人公・柴犬・像・商人の停車場所には有効な移動と作業余地を確保する。旧プレイデータの動物や建築へ木や像を上書き配置しない。互換移行できない場合は新キャンペーンが必要と明示し、無断リセットしない。

画面外の森は装飾として描けるが、物理マスを無限生成しない。行動範囲の外は濃い植生・薄い縁・ホバー説明等で判別できるようにし、敵の出現場所そのものは予告しない。F3では正確な境界を表示できる。

外周に最初からある柵・固定入口旗・その専用の通行制限を撤去する。プレイヤーが作る壁・ドアは維持。商人の来訪路／購入動物の受け入れ地点は物流用の別概念であり、敵の唯一の入口にしない。受入れ小屋は作らない。

## 2. 森と開拓

樹木の占有と、上にかぶさる樹冠の描画を分ける。幹は必要に応じて移動・施工・視線を妨げる。密度だけを一様に最大にして、誰も動けない森にしない。

初版は森の中に細い通行可能な地面を残す方式を仮案とする。侵入・退却・救出が成り立つことを確認する。敵だけが理由なく木や壁をすり抜ける実装は禁止。特別な伐採・踏破能力は定義した種／敵だけに付与する。

現在は専用道具が未実装のため伐採Jobを登録できない。選択時に「伐採には道具が必要」。以下の作業・資源条件は道具導入後の後続設計で、現在の素手能力ではない。

- 既存の仕事上限8件、選択上限8対象、停止中は計画だけを維持。
- 工期・木材収量・道具の要否は仮値として表に記録する。現時点で新しい斧購入を必須にしない。
- 対象はTreeIDで保持。同じ木の二重予約、取消、日跨ぎ、対象消失で二重報酬を出さない。
- 開拓中に動物等が入ったら占有を再検査。勝手に個体を消したり瞬間移動したりしない。
- 木を伐っても、その下の床、建物、卵、巻物等を連鎖削除しない。
- 開拓状態はキャンペーン・朝チェックポイントへ保存。朝に森を再生成しない。
- 最初は再生林を必須にしない。自然物の切り株とTreeIDの木は区別する。
- 建設ツール中に木を押すと『先に開拓が必要』。勝手に伐採予約へ変えない。
- 開拓で移動・視線・自然物生成・予定経路・侵入口候補を更新。木は屋内を成立させる壁ではない。
- 光景としての森と機能を分け、素材不足でも地形モデルを背景だけで代用しない。

開拓による判断は、建築面積・見通し・資源が増える一方、木による遮蔽や遠回りが減ること。初版で伐採へ無関係なカルマを自動加算しない。

## 3. 不定方向の侵入と退却

Stage1の固定[1,5]入口、world.entries、exit_for、敵AI、描画の旗、購入受入れが同一データへ依存していないか分離して改修する。森の画像だけ追加して固定の左入口を残さない。

各襲撃は、固定の行動範囲外周の候補からseed付きで侵入経路を選ぶ。初期は四辺に候補を持つ。全方向から常に同時に出す指定ではない。

- 主人公・動物・像のいるマス、完成壁の内部、密閉室の中へ突然出現させない。
- 有効候補、占有、通行・迂回・破壊の経路を検査する。
- 壁を建てたら敵が来なくなる／敵がその内側へワープする、どちらにも逃げない。既存の対物攻撃・迂回を使う。
- 四辺の入口と対応する外への退出位置を一組で扱う。左端への退却を全敵へハードコードしない。
- 通常の敵に、未視認の主人公位置を使って最も弱い地点を毎回選ばせない。
- 地形と襲来用の乱数列をショップ・自然発生・日誌の抽選から分離する。UIを開閉すると入口が変わる挙動を防ぐ。
- 同じ朝からやり直したとき、同条件なら同じ侵入計画になる。祈りによる意図した分岐は履歴へ記録。
- 狭い・塞がったマップでも無限探索や永久スポーン待ちにしない。失敗は明示し、内部ワープで隠さない。

『どこから来るか分からない』は事前予告の廃止であり、発見後の敵まで説明なく非表示にする指示ではない。初版で全面的な視界マスクが難しければ、森の出現前は不明、出現後は認識可能という最小構成にする。葉擦れ・遠い足音・犬の反応を使う場合も、見えない敵の正確な座標をHUDや赤線で漏らさない。

## 4. 中央の黄金像

通常の床や建築と別に、固定IDと状態を持つ重要オブジェクトにする。

保持例：id / 占有セル / 現在位置 / home位置 / hp / max_hp / installed・being_stolen・in_transit・lost / 祈り解放状態。

見た目は大きくても、選択範囲、占有、主人公が祈れる隣接位置、修理位置、敵が攻撃できる位置を別々に管理する。隣接可能性のない配置にしない。初期2×2案は実際の25×17盤面で余白を確認する。

選択で父の短い記録、祈り、必要時の修理を表示。通常の建設やタイルを像の下へ重ねず、解体・売却・収納対象から除外する。全体ドラッグで像を選んでも通常解体へ混ぜない。

被害がないときに大型HPバーを常時出す必要はない。攻撃時・選択時には危険と残り耐久を分かるようにする。黄金像の周囲を屋内にして守ることは選択肢として許可し、屋外専用の犬が救出へ入れない既存制限と合わせて判断を生む。

像の修理は現地2秒（仮）、素材1個につき土HP1・木HP2・石HP3（指定済み）を実装。通常建物・床の修理とは別方式。祈るだけで無条件に耐久が全快する隠れた仕様を作らない。

## 5. 黄金像の祈り・報酬抽選・レアリティ

祈りは「固定+60G」ではなく、**報酬カテゴリを選び、そのカテゴリの中身を翌朝ランダムに受け取る**仕組みへ変更する。

選択肢：
- **動物を願う**：翌朝、抽選された動物1匹を得る。
- **お金を願う**：翌朝、抽選されたGold量を得る。
- **アイテムを願う**：翌朝、抽選されたアイテム1つを得る。

1回の祈りで得るのは上記のうち選んだ**1カテゴリだけ**。動物・お金・アイテムを同時に得ない。

### 祈りの実行

黄金像を選択 → 願いカテゴリを選ぶ → 祈りを予約 → 主人公が像へ隣接 → 作業 → 祈り成立 → **次の夜明けに抽選・受取**。

祈りは通常の仕事枠を1件使う。祈り中・予約済み・今日の祈り済み・像が搬出中／消失・到達不能を区別する。

- 1晩1回制限は祈り成立時に消費（回数は仮）。
- 成立前に取消／中断した場合、報酬予約・カルマ変化を確定しない。
- 成立後はUIを閉じても結果を取り消せない。
- PAUSE中は作業・祈り時計を進めない。
- 被弾・気絶・運搬・強制休息と既存ルールで競合させる。
- PrayerID、願いカテゴリ、成立日、受取日、抽選seed、受取状態、カルマ反作用状態を保存する。

### 共通レアリティ

スキル・アイテム・動物・敵に共通のRarityを持たせる。

**Common / Uncommon / Rare / Epic / Legendary（仮）**

ラベル・色・確率は調整前。Rarityは強さだけでなく希少性・特殊性を表してよい。

### カルマと抽選

- **カルマが高いほど、黄金像の動物／アイテム抽選で高レアリティの重みが上がる。**
- 高カルマでも高レアが確定するわけではない。
- ショップの動物／商品にも抽選要素を持たせられるが、**黄金像はショップより高レア個体・高レア追加スキルを引きやすい**。
- 正確な確率・天井・カルマ補正式は未定。通常UIへ数式を出さない。
- 「お金」にはRarityを無理に付けず、金額テーブルを別に持つ。カルマで金額まで上げるかは未確定。

### 動物報酬

- **柴犬は黄金像の抽選対象外。** 初期からいる固有の愛犬として維持する。
- 抽選された動物は翌朝、既存の購入動物と同じ安全な受入れ処理で園内へ加わる。
- 受入れ場所がなければ受入待ち。密閉室や他個体の上へ瞬間配置しない。
- 動物自体のRarityと、個体追加スキルのRarityを別に持てる。
- 稀に珍しい追加スキルを持つ個体が出る。種族固定スキルとは別。
- 黄金像はショップより珍しい追加スキルの抽選率が高い。
- HP0で死亡しない例外は柴犬だけ。黄金像から得た動物も原則HP0で死亡する。

### アイテム報酬

ITEMS.mdの抽選可能なアイテムから選ぶ。装備・消耗品・巻物等を混在させる場合はLootTableで管理し、未実装アイテムを名前だけ出さない。

### 実装済みと未確定の境界

祈りを使わない基礎ルートと3カテゴリの祈りは接続済み。祈り完了時はカテゴリを問わずカルマ+3。継続利用補正・時間減衰・高Rarityアイテム表・カテゴリ固有勢力は未確定または未実装であり、現行値へ混ぜない。

## 6. 世界情勢と遅れて届く反作用

カルマは敵の出現条件にも使う。低カルマではHuman / Animal系だけを候補にし、高カルマになるほどInfected / Mutation / Cult / Military / Alien等の異常系TypeTagや高Rarity敵を解放できる。閾値は未確定。

敵出現は全て完全ランダムにしない。**序盤の数ステージは固定遭遇、以後はテーブル抽選を増やし、定期的に固定の節目遭遇を挟む**。各夜をFixed / Table / Hybridとして定義できる構造にする。具体的な敵データとTargetWeights等はENEMIES.mdを正本とする。

最初から独立した6本の巨大シミュレーションを作る必要はない。少なくとも次の構造を持つ。

- WorldState：治安リスク、経済の状態、感染リスク、異常、像の認知、祈り蓄積。名称・範囲は仮。
- WishEvent：PrayerID、種類、成立日、報酬、効果タグ。
- WorldEvent：EventID、元のPrayerID（自然発生なら無し）、発生日、公開段階、ニュースID、機械的効果、適用済み状態。

純粋な世界ロジックをUIから分離する。描画回数・実時間・ショップを開く回数で内部値が変わらない。スキップ、朝へのやり直し、日跨ぎでも一意に適用する。

富を実装する最小例（間隔・強さは仮）：

- 日D：富を願う。
- 日D+1：報酬、金鉱脈発見等の関連ニュース。
- 日D+2以降：物流・治安への影響が、商人の短い話や襲撃構成に現れる。
- 繰り返し利用：像の噂が広がり、像を狙う目的の敵が候補になる。

ニュース用の架空話と機械的な世界状態を別々に抽選しない。世界で起きた同じイベントから、ニュース・商人・敵候補を派生させる。ただし毎回同じ日数で同じセリフを出して答え合わせにしない。

初版では富→治安／噂に絞り、疫病・宇宙現象の値はデータ枠だけでもよい。未実装の感染者や宇宙人を、名前だけ変えた通常敵として『完成』にしない。

基本の夜の危険と祈りによる追加危険を別にする。既存の日数強化へ祈りの強化を無制限に乗算しない。序盤の上限、予兆、対処時間を設ける。祈らない比較プレイでも基礎襲撃はあるが、像の反作用イベントは祈りを使う場合と異なる。

経済への効果を入れる場合は、価格が取引クリックの途中で変わらないよう朝の在庫生成で固定し、買値>売値、単位、セット数、重複決済を維持する。経済変動は後続でもよく、初版で全商品価格へ理由なく一律倍率を掛けない。

通常HUD、図鑑、ショップ、ツールチップへカルマ数値や因果IDを出さない。F3には検証用として表示・操作してよいが、DEBUG表示と通常画面を明確に分ける。

## 7. ラジオ・商人・父の記録

ラジオの入手は永続的な所有状態として記録し、朝ごとに取得し直さない。初期案は2日目に無料入手。素材未納品の間の仮表示と完成品を区別する。

ラジオ・父の記録・ニュースの保存データは維持する。旧朝入口の記録／回想ボタンは撤去済み。日開始に短い情報を見せる設計意図と、現行の再読導線の不足を区別し、専用朝画面が存在するとは説明しない。会話・ショップ・図鑑の停止中もUI演出は進む。

再読できる放送履歴と父の記録を用意する。個体の育成ページへ関係ない物語テキストを無秩序に混ぜない。取得済みの日誌はItemID／StoryFlagで管理し、売却や開閉で同じ手掛かりを何度も解放しない。

ニュースの再表示とWorldEventの発火は別。ラジオを読むたび敵が増える、値が上がる、Goldが増える挙動を禁止する。ラジオ入手前に起きた反作用も消さず、必要なら後から要約して知れる。

商人の台詞は世界情勢・噂に合わせて少し変わるが、取引結果の通知と競合させない。ショップUIレビューの数量・結果・戻る導線改善は独立して維持する。

父の消息、像を壊せない理由、終盤の真相は未公開／未確定。ゲーム開始時の説明へネタバレを混ぜない。

## 8. 像を狙う敵と救出

初期誘拐者は従来どおり主人公を狙い、像の正体を知らない。像の認知が進んだ後に、像破壊・搬出という目的を段階追加する。目的は属性で管理し、敵の見た目追加と切り離す。

像破壊：対象へ接近 → 対物攻撃 → 像HP0で喪失。通常壁への攻撃と、像を狙っている攻撃を通知と状態で区別する。

像搬出：像へ接近 → 固定を外す等の準備 → 牽引／台車で低速移動 → 外側の搬出地点へ到達 → 喪失。人数・準備秒数は仮値として指定し、巨大像が一人の肩へ瞬間に縮む表現は禁止。

少なくとも preparing / transporting / interrupted / recovered / lost を分ける。必要な搬出担当が撃退されたら、その場で搬出を中断する。像を自動で中央へ瞬間帰還させず、回収・再設置の方法と通路幅を定義する。初期2×2案のまま狭い1マスドアへ運べると仮定しない。

柴犬の救出本能の対象を主人公だけにするか、像の搬出担当も優先するかは別の補足仕様。初期案は主人公の救出を最優先、像の危険は既存攻撃／指示から対応する。犬の屋内禁止は維持。

動物や通常施設の損失は被害であり、それだけで主要敗北にしない。家畜窃盗・儀式などを追加する場合は専用の解決条件を定義する。

## 9. 勝敗、夜明け、やり直し

主要敗北理由を明示する：keeper_abducted / idol_destroyed / idol_stolen。同じ更新で複数条件が成立しても結果処理は一度だけ。夜明けや早期撃退の勝利表示より、既に成立した喪失を優先する。

夜明け時に主人公／像が搬出中の場合、日替わりによって運搬者を消して救出完了にしない。初期の補足案は、その危機が解消するまで次の日へ進めないこと。明け方の表示と危機継続を両立し、新たな襲撃を無限に足して引き延ばさない。

像・森林・祈り・放送・世界イベント・敵目的を、既存の朝チェックポイントへ含める。『朝からやり直す』では当該朝の状態へ一括で戻す。一部の報酬だけ残し、反作用だけ取り消す抜け道を作らない。

現状のキャンペーン永続セーブが未実装なら、アプリ終了後にも保存されると説明しない。復元可能なデータ形状は用意し、UI設定保存をゲーム全体の保存と混同しない。
