# 製作・満腹度・スタミナ — 基本設計（未実装案）

更新：2026-10-14。状態：**企画・基本仕様案（実装指示ではない）**。

本書はホイッスル牧場の次期拡張候補を定義する。製作・動物を含む新しい満腹度／スタミナ連動は**まだ実装済みと扱わない**。数値・設備費用・料理効果は調整可能な初期値。現在動く仕様は [GAME_SPEC.md](GAME_SPEC.md) および [PROJECT_STATE.md](PROJECT_STATE.md) を参照する。

## 1. 採用する骨格

- 最初の製作設備は **調理台／木工作業台／裁縫台** の3種類。生産物を料理・生活家具・衣服に分けるが、**共通の製作システム**を用いる。
- 製作レシピは「設備ID、素材種と数量、完成品と数量、作業時間、必要技能（当面任意）、効果」をデータで定義。レシピを増やしても実行エンジンを分岐させない。
- 製作指示は「指定数量」「在庫数維持」の2種類を初期候補とする。「素材がある限り作り続ける」は後続候補。初版は品質ランク・複数工程ライン・技術研究は持ち込まない。
- 既存の **1回の運搬容量20／備蓄40個・マス／プレイヤー仕事予約100件** と矛盾しないようにする。製作指示を毎tick無限に仕事登録しない。
- 既存の物理在庫（地面・備蓄・携行・現場、予約、禁止、消費）を用いる。素材や完成品を画面用の仮想在庫へ直接増減させない。
- 製作専任職がなくても開始できるよう、初版は既存「その他」または「建築」等の作業カテゴリから割当可能とする。正式な「製作」優先度追加は別判断。
- 「レシピ」「素材の追加」「生活効果」はそれぞれ独立して増やせることを重視する。

## 2. 共通の製作フロー

1. プレイヤーが設備を選択し、製作物・数量・方式を指定する。
2. 未禁止で未予約の素材を備蓄から確保する（ほかの建築・食事・製作と二重確保しない）。
3. 住人が素材を運ぶ。20個で足りなければ複数便。運搬中はその現物IDを保持する。
4. 材料が必要数揃ったら作業者が設備の近くで製作。時間を進捗として記録する。
5. 完成時に材料を一度だけ消費し、完成品を設備付近へ**現物として生成**する。
6. 完成品は回収／搬入で備蓄に入る。食事・着用・売買・次のレシピに使用できる。

**中断・競合**：空腹／低スタミナ／危険／休息／他の予約／通路閉塞／設備破壊では必要な理由を残して待機・中断。既に搬入した素材と進捗は保持し、再開時に重複消費しない。設備を取消・解体した場合の未使用素材は現物として返し、消失させない。製作指示の上限と既存100仕事との数え方は実装前に決定する。

**製作指示UI（最小）**：設備クリックで「レシピ／数量／製作中・待機理由／必要・搬入済み素材／完成数」を表示。「指定数作る」「在庫がN個未満なら補充」の設定を共通化。料理・家具・服ごとに別画面構造を作らない。

## 4. 食事に意味を持たせる：満腹度とスタミナ

### 指標と役割

| 指標 | 範囲 | 意味 |
|---|---|---|
| 満腹度 | 0〜100 | 食事によって増え、時間経過で減少。**最大スタミナと回復速度**を左右する |
| スタミナ | 0〜現在の最大値 | 仕事・継続移動・運搬・戦闘等で減少。休息・待機・軽い徘徊で回復する |
| HP | 現行値 | 負傷・飢餓ダメージ。満腹度と別に保持 |
| 眠気／休息 | 現行値 | 睡眠・休息を扱う。スタミナへ統合せず別指標のまま維持 |
| 一時効果 | 効果ID＋残り時間 | 料理や装備によるバフ・デバフ。重複規則を共有 |

スタミナは**住人と飼育動物の全対象**に用意する。既存の人間の満腹度・栄養失調・一部個体のスタミナと二重に減算しないよう、最終的に計算源を一本化する。動物の種類による例外は食性・行動係数で表現。

### 満腹度によるスタミナ上限・回復倍率（初期案）

| 満腹度 | 現在の最大スタミナ（初期基準100） | 自然回復倍率 | 状態 |
|---|---:|---:|---|
| 76〜100 | 100 | ×1.0 | 良好 |
| 51〜75 | 90 | ×1.0 | やや空腹 |
| 26〜50 | 80 | ×0.75 | 空腹（**50%で最大80**） |
| 1〜25 | 60 | ×0.5 | 強い空腹（**25%以下で最大60**） |
| 0 | 40 | ×0.25 | 飢餓。後述の追加ペナルティとHP減少 |

- しきい値はパラメータ化し、数値は試遊で調整する。満腹度低下で上限が下がるとき、現在スタミナが上限を超えていたら新上限へ切り詰める。
- 初期状態は **満腹度100／スタミナ100** とする。
- 満腹度の減少は時間を基準とし、作業・活動負荷による追加減少は初版では小さくする。既存の空腹処理と重複計算しない。

### スタミナの変動（基準案、ゲーム内秒）

| 行動 | スタミナ変化／秒（案） | 補足 |
|---|---:|---|
| 何もしない・待機 | +3 | 現在の上限まで回復 |
| 軽くうろうろ／自由散歩 | +1.5 | 回復しつつ移動可能 |
| 休息・睡眠 | +5 | 眠気回復は別処理 |
| 継続歩行（目的地へ移動） | −1 | 仕事の移動にも適用 |
| 建築／採集／調理／製作 | −3 | 仕事カテゴリ別係数を後で設定可 |
| 重い運搬 | −2 | 継続歩行の代わりに適用、二重減算しない |
| 戦闘／特殊行動 | 個別 | 既存戦闘スタミナとの整合を優先 |

残量が低いときは新しい仕事を開始せず短い休憩へ。0でも身動きが取れない無限ループを作らない（危険回避・食事へ行くための最低限の行動は可能にする）。回復待ち→仕事復帰を繰り返して右往左往しないヒステリシスを設ける。初期案は **20以下で休憩開始／60以上で再開**。

### 満腹度0：飢餓

- 満腹度0で飢餓状態を開始。最大スタミナ40・回復×0.25、移動／仕事効率低下、一定の猶予時間経過後に徐々にHPダメージ。
- 食事を摂れば満腹度を増やし、飢餓進行を停止。重度の栄養失調からの完全回復には時間がかかる案とする。
- **既存の栄養失調による行動不能・死亡処理とは統合**し、同じ飢餓で二重にHPを減らさない。既存人間キャラの最終的な敗北条件は [WORLD_SYSTEMS.md](WORLD_SYSTEMS.md) と照合する。
- 柴犬は既存の「HP0では死亡せず気絶」を守る。他の動物の死亡規則は [ANIMALS.md](ANIMALS.md) の個体設定を維持。
- 飢餓ダメージ開始までの猶予・間隔・値は未確定。ゲーム内1日が現在約432秒の暫定設定である点を踏まえ、試遊で固定する。

### 動物の食事と行動

- 全飼育動物に満腹度・スタミナを持たせる。既存の動物生産・敵迎撃・調教・連行・睡眠AIを壊さない。
- 食性は種別データで管理（例：柴犬・猫は肉系／鶏は穀物・雑食／草食動物は草）。**食物がゲーム内に存在しないため餓死する**ことがないよう、初版で実際に取得できる餌の供給ルートを先に決める。
- 野草の採食を可能にする場合も、無料で無限の栄養を作らず、既存の地形／採取ルールと接続する。飼料台・飼料加工は後続候補。
- 主人公・住人の「製作した料理」と動物の「餌」は食性を満たす場合のみ共通在庫から消費。動物への料理バフの適用可否はレシピ・種別ごとに定義。
- 低スタミナの動物は休息を優先。ただし敵からの逃走・救出・特殊スキルは既存優先規則を維持。

## 5. 料理バフ／デバフの基本規則

- 食品データは満腹回復量に加え、効果ID・倍率・持続秒・対象種別を持つ。例：卵料理＝自然回復+20%／60秒、煮込み＝仕事効率+10%／90秒（仮）。
- 効果はゲーム内時間で減衰。**同じ効果は重複加算せず残り時間を更新**。異なる効果の併用は上限を設ける（初期案：効果カテゴリごとに1つ）。
- デバフ候補：生食の食あたり、傷んだ料理による一時作業効率−10%。**食品の腐敗システムは初版未導入**なので、デバフ導入は既存の生食品扱いの再検討後。
- 満腹100時に追加で食べ続けるバフ稼ぎを防ぐ（自動食事は空腹基準。バフ目当ての任意食事は初版保留）。
- 自動食事の優先順位：必要な食性と空腹回復を優先し、希少な料理の無駄食いを避ける。料理がなくても既存の生食品で生存可能なバランスにする。
- 調理後の食品も現物台帳上に1種類として保存。禁止・搬入・売買・盗難・消費は既存ルールに従う。

- 人・動物の状態カードで **HP／満腹度／現在・最大スタミナ／眠気（人）／食事効果** を表示する。

## 8. 雑草→繊維と備蓄ゾーンの分類（2026-10-14 追加設計）

### 雑草回収：繊維の入手先

- **採用する方向**：マップ上の「雑草（weed）」を回収すると「植物繊維（fiber）」を**現地に現物として生成**する。初期案：雑草1株→繊維2個（数量は仮）。現物の回収／備蓄への搬入は既存の「回収」仕事で行う。直接どこからでも使える共有在庫へ加えない。
- 繊維は当面、一部の初級衣服（例：**草繊維の服＝繊維6個**、仮）に使う。布・革を経由しなければ1着も作れない設計にはしない。高度な衣服は布・革を別途使う。
- **現行動作との差**：今の world.gd は雑草回収時に `campaign.gold += Rules.NATURE.weed_gold` を実行している。ゴールドを繊維に**置き換えるか**、両方得るかはバランス判断が必要。**推奨は繊維へ置換**し、雑草回収を繊維の主な獲得源にすること。ただし未承認のゴールド報酬削除を既成事実化しない。
- 雑草の再出現・採取効率が繊維供給量を左右する。必要繊維が尽きたときの詰みを防ぐ供給量は初期衣服レシピの確定前に調整する。
- **状態**：製作・繊維用途の設計。ゲーム本体への反映・EXEへの反映はまだ行っていない。

### 既存備蓄の確認

- 現行ゾーンは複数作成でき、ゾーンごとに6分類（土・木材・石・食料・装備・その他）の受入ON/OFFがある（game/colony_zones.gd、game/zone_controls.gd）。
- 現状の運搬は「現地から備蓄へ運ぶ」**明示回収仕事**が原則であり、ゾーン間の自動再配置は未搭載。受入設定を変えただけで既存の物資が自動的に動くと説明しない。
- 製作でも **選択した製作物→備蓄にある利用可能な材料を予約→備蓄から設備へ搬入→製作→完成品を現地に現物生成→回収して備蓄へ** を基本とする。製作専用の新しい資源管理台帳を増やさない。素材確保と設備への搬入は内部工程で、プレイヤーが二度予約しない。

### アイテム分類の設計

**「主カテゴリ＋サブカテゴリ」は各アイテムに一意**、**「用途タグ」は複数可**とする。保存先のフィルターは主／サブ／個別アイテムを対象にし、製作可能性は用途タグに頼らずレシピの素材IDで判定する。用途タグはUIの絞り込みと将来の拡張に使える。

| 主カテゴリ | サブカテゴリ例 | アイテム例 | 用途タグ例 |

| 資源・素材 | 土砂石材／木材／金属原料 | 土、砂、石、木材、鉄鉱 | 建築、加工 |
| 資源・素材 | 繊維・皮革／加工部材 | **繊維**、布、革、鉄材、釘 | 裁縫、加工、建築 |

### 備蓄フィルター・優先度の初期案

1. ゾーン選択→「保管設定」を開き、**全許可／全禁止、主カテゴリ、サブカテゴリ**の許可チェックを設定する。必要に応じて個別品目まで絞り込み可能にする。
2. 例えば**厨房の備蓄**：食料＞生食材を許可、資源・医療品を禁止。**工房の備蓄**：木材・繊維・布を許可。**総合備蓄**：広く許可。
3. 優先度はまず **高・通常・低** の3段階。品目を置ける複数のゾーンがあるとき、高優先度を優先し、同順位は距離／既存同種スタック／空き容量／到達可能性で選ぶ。備蓄の40個／マスは維持。
4. 同じ種類の物資を遠方の備蓄から厨房近くへ自動で動かすかは**別仕様**。初期段階は既存の明示回収の目的地選択と製作の素材取得へフィルター・優先度を反映する。**自動仕分け・高優先度への補充**は後続案（導入するなら運搬作業を生成し、既存の仕事優先度・容量20・在庫予約と重複しないようにする）。
5. 設定変更後に不許可になった既存の物資は**削除／即時移動しない**。不許可として表示し、ほかの受入先への移送方法と利用可在庫の扱いを一貫させる。既存6分類ゾーンは「全許可」を維持し、制限付きは旧意図を反映した移行規則を設ける。
6. 製作台はゾーンの種類ではなく**必要素材ID・備蓄済み・未予約・未禁止**を基準に素材を確保する。複数備蓄を走査する際に必要なら近い備蓄の素材を選ぶ。明示的な作業台専用の備蓄指定は初版不要。
