# 地表・スクロール計測

1280×800、RTX 4070 SUPER / OpenGL 3.3 compatibility / Godot 4.7.2、非対話GPU、Dummy音声、60fps上限、直列3回。通常1050px/sを維持。各条件5秒×3回を合算。単位ms。beforeは5b4a351のゲームに観測用タイマーだけ追加、afterはDELIVERY.jsonの実装ツリー。全フレーム・処理別タイマーは両scroll-performance.jsonに保存。

startupは初期化完了後の最初の描画から5秒。normalは倍率1、fastは倍率0.5で同じ画面速度（世界では2倍距離）、boundariesは倍率0.8の斜め移動。静止・移動とも通常世界tickあり、Godot内のキー状態を使用。OS操作なし。撮影読み戻しは計測後。上限待ちを含む実フレーム時間なので平均16.67msからGPUの限界FPSは推定できない。CPUタイマーは包含関係があり足し合わせない。

## 原因と対応

- beforeの自然物候補走査は約69〜87ms。キャッシュ済みの地表重みから候補を抽出し、その地点の現在の占有を検査する方式へ変更。発生率、上限、種類の重み、床・占有の禁止条件を維持。抽選手順変更により過去版と全く同じ座標列にはならないが、新版内のseed・乱数状態は再現可能。
- beforeは初表示区画で地表メッシュを作り、境界越え時に約10〜28msの描画処理が集中。新地表は3層から1層へ統合し、117区画の形状と装飾候補を初期化時に準備。スクロール中は保持済み描画を再利用。占有の変化で必要な区画だけ再描画。
- 新旧ともカメラ速度は1050。通常スクロールの25ms超はafterで0回、高速では4/900程度残る。正確な件数は上表。最終afterはスクロール3条件で50ms超なし。
- 途中測定では初表示124ms、同一プロセスのマップ作り直し時42〜61msが残った。後者では主シーン描画が29〜48msを占めたため、前マップを参照する切り株描画キャッシュも初期化時に更新した。最終3回では起動後5秒の最大22.76ms、主シーン描画最大4.26ms。旧マップ参照の解放／再構築の遅延が初期化へ移ったと考えられる。
- **冷間起動の限界**：初回素材読込は計測しているが、OS・GPUドライバーのキャッシュは消していない。最初の124ms全体の原因はCPUタイマーだけでは特定できず、シェーダー／ドライバー準備は推定。最終の22.76msを「PC再起動後も必ず保証」とは扱わない。

- ほぼ全面が塞がった場合は、32回の棄却後に有効地点を正確に走査する。地点なしなら生成しない。床の検査を先にし通常の高速経路へ影響させないが、極端な占有マップのGPU長時間計測は未実施。

## 起動待ち

- before: 14336ms, 3255ms, 2846ms（1回目は素材読込を含む、2〜3回目は同一プロセスで読込済み）。
- after: 7486ms, 3300ms, 3056ms（1回目は素材読込を含む、2〜3回目は同一プロセスで読込済み）。

全景用キャッシュ準備で起動待ちは増える場合がある。待ちをスクロール速度低下で隠していない。通常の30fps制限だけでは見えなかった自然物・区画生成の停止を今回60fpsで再現・修正。人間の入力快適さや他PCでの無停止は保証していない。
