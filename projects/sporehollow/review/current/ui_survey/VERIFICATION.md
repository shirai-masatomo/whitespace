# 検証方法と限界

## 今回行ったこと

- 最新ローカルHEAD・通常EXEの配布記録・ゲームソースを照合。ゲーム85ファイルは実装9624a29と一致。
- 専用Window Station / 非対話DesktopでGPU描画。1280×800、30fps上限、DummyAudio、直列1プロセス。正常終了、タイムアウトなし。
- 通常のmainシーンを使用。画面操作コールバックと、条件設定したfixtureから64枚のPNGを保存。
- 64保存チェック＋6補助チェックが成功。ただし補助には「十分な枚数」も含むため、70のゲーム仕様を検証した意味ではない。
- 徴兵中の通常仕事ボタンdisabled、建築予約→World.stepで完成、商人への交渉予約→現地接近→メニューを確認。
- 購入／売却、隔離セーブの保存／同一プロセス内読込を実行し画面化。日付境界はWorld.stepで1tick進め、敵残留表示を確認。
- 原寸PNGから主要画面の切れ、重なり、文字、素材、数量、夜間操作を点検。

## 成功と不合格を区別

**撮影成功、総合品質は未合格。** 動物選択時の描画型エラーを検出したため [ui-errors.json](ui-errors.json) の `visual_test_passed` はfalse。例外を隠して合格にしたり、今回修正したことにはしていません。

最初の収集では既存ランナーがゲームエラーを理由に全画像を引き渡さなかったため、レビュー専用ランナーを「正常終了・隔離確認を必須とし、描画エラーは不合格のまま原本へ記録」に変更しました。失敗画像を成功証拠へすり替えず、不具合がある現状を撮っています。

## テスト条件

seed31の通常開始を基準にし、必要に応じて鶏・猫追加、敵知識、所持金0、2日目の像損傷、夜間と敵1体を設定。各画像のfixtureはSCREENSに明記。敵の近傍配置は夜間表示確認用で、通常出現ルートの検証ではありません。本の途中フレームはUI時刻を指定した静止画で、動画ではありません。

自動コールバック／fixture確認は、人間の実マウス操作や快適さの評価と同一ではありません。全商品・全種・全Tooltip・全画面サイズの網羅はしていません。64枚は主要画面と代表状態です。

通常EXEの終了→別プロセス再開5項目は [前回の配布記録](../mountains/DELIVERY.json) に残っています。今回の再実施結果として合算しません。大量の全回帰・AI長時間試験は行っていません。今回のゲームコード変更はありません。
