# 既存素材による作業モーション試作

2026-10-14。実装基点11b92eac。素材ブランチ最新adb33aa07da2ec57959e0315963f15003ddcd085を確認。
指定のwork_pose接触4枚だけを原寸・無加工で取り込み、原本manifest/HANDOFF/出典・採用記録を保持した。

## 実装

- 採掘・伐採：歩行→既存人物と仮道具による振りかぶり→正式接触ポーズ→既存人物と道具の戻りを反復。
- 実際のHarvest.strikeイベントから接触を表示（0.18世界秒）。既存の石片・木屑・打撃音と同じイベント。
- 右は足元(28,56)、左は(52,56)、80×64、表示1.4375倍。通常人物と同じ足元を使用。
- 接触時は全身1枚を差し替える。元人物・仮道具を同時描画しない。対象のx方向で左右を選び、上下同xは現在の向きを維持。
- 建築：施工進捗から0.75秒周期の振りかぶり／打撃／戻り。搬入・採掘・製作などには建築ハンマーを出さない。
- 中断・取消・休息・食事・危険・徴兵・移動・完了では通常描画へ復帰。PAUSEで進まない。
- 登録住人も同じWorkMotionを利用。現在の登録住人の既存人物絵を維持。
- HarvestViewの古い道具描画と、主人公の汎用ハンマー描画を撤去。建築完了エフェクトは変更なし。

処理はwork_motion.gd／harvest_view.gd／main.gdの表示側。World、HarvestWork、建築施工、採掘・伐採時間、収量、資源・仕事の更新コードは変更していない。
4画像を事前ロード。実行中のget_image・画像合成・地形探索なし。既存イベント走査に接触記録を追加し、人物描画は辞書参照＋最大数個の図形。通常60fps上限を維持。

## 検証と確認画像

- work-motion.json：50チェック、失敗0。左右、実World.stepの打撃イベント同期、作業完了、搬入時抑止、休止、住人共用、表示の非破壊性。
- 216サンプルすべて人物1枚。採掘・伐採・建築×左右×36フレームの描画命令を検査。
- harvest.json：28チェック、失敗0（現物生成、部分採掘、進捗保持、複数住人等の既存回帰）。
- construction-groups-normal.json：31チェック、失敗0（搬入→施工、容量・数量の既存回帰）。
- loading.json：39チェック、失敗0。既存の終了時ObjectDB警告1409は残る。今回で解消したとは扱わない。
- asset-checks.json：4PNGのSHA256・80×64・RGBAが素材manifestと一致。

合計148ロジック/UI読込チェック＋4画像検査。headless・Dummy・30fps上限・低優先度・各120秒の停止条件。
通常ゲーム・GPU試験は実施していない。実機FPSや操作感の改善を実証したものではない。

[確認画像](SCREENS.md)：同じWorkMotion.paintが出した描画命令をCPUで描画。
比較PNGは歩行・振りかぶり・接触・戻り・通常復帰の左右6行。GIFは12fps、3秒。
実ゲームのスクリーンショットではない。原画の加工や新規生成ではなく、表示位置・重なり・ポーズの比較用。
画像を目視し、固定足元、左右の人物差替え、道具の非重複を確認した。

## 不足・未検証

- 採掘／伐採の振りかぶりと戻りは仮道具。将来は同じ80×64・左右アンカーの全身コマが必要。
- 建築は正式な全身3段階（振りかぶり・打撃・戻り）が不足。現在は既存idle人物＋ハンマー。
- 登録住人に固有の外見を導入する場合は、その外見の対応ポーズが必要。
- 通常画面での周辺物との遮蔽、各ズーム、実GPUフレーム時間、実機操作は未検証。
- 接触素材の道具先端は納品位置を維持。上下向きの専用コマはなく、無理に道具や人物を伸ばさない。
